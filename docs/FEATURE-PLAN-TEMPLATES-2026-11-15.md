# FEATURE PLAN: Библиотека шаблонов dsh-ppt (2026-11-15)

Статус: черновик на согласование. Реализация — после одобрения.

## 1. Цель

Добавить в плагин dsh-ppt полноценный механизм шаблонов презентаций:

1. **Создание презентаций из шаблонов** — ppt_create / панель / CLI принимают шаблон
   из библиотеки и порождают черновик дека в его стиле и структуре.
2. **Создание шаблонов из примеров PPTX** — импорт существющего .pptx: извлекаем
   стиль (палитра темы, шрифты, фоны мастеров/макетов, логотип) и структуру
   (заголовки слайдов) → новый шаблон.
3. **Проект → шаблон** — превращение существующего dsh-ppt проекта в шаблон
   (стиль + каркас страниц + слайды-образцы).
4. **Импорт/экспорт шаблонов** — переносимый bundle (.zip: template.json + ассеты).
5. **Админ-функции** — импорт общедоступных шаблонов из файлов, редактирование
   общего списка (правка меты, удаление, публикация личных шаблонов).
6. **Личная библиотека** — каждый пользователь добавляет свои шаблоны
   (с нуля / из pptx / из проекта) и видит их рядом с общедоступными.
7. **Редизайн существующего проекта шаблоном** — применить стиль шаблона
   (тема, палитра, шрифты, логотип, футер, фоны) к готовому деку, сохранив
   весь контент: через инструмент, панель и CLI; обратимо через undo.

## 2. Принятые решения (согласованы)

| Вопрос | Решение |
|---|---|
| Состав шаблона | Стиль + каркас структуры + слайды-образцы; каждая часть опциональна |
| Глубина импорта PPTX | Извлечение стиля через `@office-kit/pptx` (уже в зависимостях); v1 извлекал стиль; v3 сохраняет геометрию поддерживаемых объектов в исходных EMU |
| Кто админ | Модель плагина auto-memory: личность = `session.header.owner`; хост (webAuth) — источник истины; конфиговый список `admins` — запасной; без owner (локальная/CLI-сессия) → админ; делегированная сессия → никогда не админ; fail-closed |
| Откуда общедоступные | Импорт файлов (.zip/.json) админом: загрузка в панели + путь через инструмент; без URL-загрузки |
| Публикация личного в общий | Только админ (копия личного шаблона в общий список) |
| Контент «проект → шаблон» | Стиль + структура + слайды-образцы (черновик с плейсхолдерами) |
| Редизайн проекта шаблоном | Режим `style`: меняется только оформление (theme/brand/фоны), контент и порядок страниц не трогаются; in-place + undo; пересборка структуры (restructure) — вне v1 |
| Фоны слайдов из шаблона | Новая ограниченная движковая возможность (сейчас фонов-картинок нет): HTML-слой + PPTX `setSlideBackgroundImage`; шаблоны без фонов работают всегда, при отсутствии поддержки — предупреждение |
| CLI | Поддерживается: команды работают с файлами шаблонов из любой папки |
| Встроенные шаблоны | 1–2 в комплекте плагина, созданы нашим же импортёром из pptx-примеров |

## 3. Формат шаблона

### 3.1 Манифест `template.json` (schemaVersion 1)

```jsonc
{
  "schemaVersion": 1,
  "id": "corporate-blue",          // slug: [a-z0-9][a-z0-9-]{1,48}
  "name": "Corporate Blue",
  "description": "Фирменный синий стиль по шаблону компании",
  "author": "alice",                // логин создателя; у встроенных — "dsh-ppt"
  "revision": 3,                    // растёт при каждом сохранении
  "createdAt": "2026-11-15T10:00:00.000Z",
  "updatedAt": "2026-11-15T12:30:00.000Z",
  "style": {
    "theme": "data",                // базовая тема из 5 встроенных (осуществляет рендер)
    "brand": {
      "primaryColor": "#1B4FD8", "backgroundColor": "#F5F8FF", "textColor": "#10224A",
      "fontFamily": "Arial", "logo": "assets/logo.png", "footer": "© ACME 2026"
    },
    "backgrounds": [                // опционально: фоны по типам страниц
      { "layout": "cover",   "image": "assets/bg-cover.png", "fit": "cover" },
      { "layout": "content", "image": "assets/bg-content.png", "fit": "cover" }
    ]
  },
  "outline": [                      // каркас страниц-заготовок (каждая опциональна)
    { "layout": "cover", "title": "{{deck.title}}",
      "subtitle": "Заполнить: докладчик и дата" },
    { "layout": "bullets", "title": "Заполнить: раздел 1",
      "bullets": ["Заполнить: конкретные факты, доказательства и следующий шаг"] }
  ],
  "samples": [ /* опционально: 1–3 слайда-образца с реальным контентом для вдохновения */ ]
}
```

Правила применения шаблона при создании и редизайне:

- `style.theme` + `style.brand` уходят в создание/редизайн как обычные
  `theme`/`brand` (весь рендер уже идёт через brandedTheme(manifest)).
- `style.backgrounds` применяются по типу страницы (cover/section/content/closing);
  поддержка фонов — новая движковая возможность, см. §7.6. Шаблон без фонов
  полностью работоспособен на текущем движке.
- Страницы собираются из `outline` (с подстановкой `{{deck.title}}` и т.п.),
  затем `samples` (если автор шаблона их оставил) — помечаются как образцы.
- Плейсхолдеры «Заполнить: …» («To fill: …», «待填写：…») уже распознаются
  движком: ppt_check даёт `template-unfilled`, дек получает
  `deliveryStatus: draft`. Своего механизма слотов не требуется.
- В манифест дека записывается происхождение: `template: {id, revision}` —
  видно в ppt_check/панели (по аналогии с dataModel-lineage).

### 3.2 Bundle импорта/экспорта

- `dsh-ppt-template v1` = ZIP (`fflate`, уже в зависимостях):
  - `template.json` — манифест;
  - `assets/*` — логотип, фоны (png/jpeg);
  - `README.txt` — человекочитаемое описание (по образцу delivery-bundle).
- Принимается и «голый» `template.json` (шаблон без ассетов).
- Экспорт всегда zip; имя файла `<id>-template-v<revision>.zip`.

## 4. Хранилище

```
$DSH_HOME/plugins/dsh-ppt/
  templates/
    public/            # общедоступные; пишет только админ
      corporate-blue/  # каталог на шаблон: template.json + assets/
    users/<login>/     # личные шаблоны пользователя
      my-tpl/
  created/             # деки, созданные из шаблонов прямо в панели
```

- Один каталог на шаблон (не одиночные файлы) — атомарные записи,
  не нужен индексный jsonl: список строится сканированием каталогов
  (количество шаблонов исчисляется десятками, кэш в памяти процесса).
- Встроенные шаблоны лежат в пакете плагина (`assets/templates/*.zip`),
  регистрируются как `builtin:` только для чтения.
- Ключ шаблона: `<scope>:<id>`, scope ∈ `builtin | public | user:<login>`.

## 5. Админ-модель (повторяет плагин auto-memory)

Новый `src/identity.ts`:

1. **Инструментальная плоскость** (`ppt_template`, `ppt_create`):
   - личность только `exec.agent.session.header.owner`;
   - делегированная сессия (fork-ребёнок / fleet) → не админ;
   - `owner === undefined` → локальная/CLI-сессия → админ;
   - иначе спросить хост через webAuth-мост (`adminResolver`): true/false —
     авторитетно; `undefined` → запасной список `admins` из конфига плагина
     (сравнение trim, регистрозависимое);
   - всё сомнительное → не админ (fail-closed).
2. **Панель** (workbench fetch): расширить `web-owner.ts` —
   `webAuth.identityFromCookie(cookie) → {login, admin}`; роль из куки
   авторитетна; `admin !== true` на админ-операциях → 403.
3. Конфиг плагина: `PptConfig.admins: string[]` (не выводится в панель
   настроек; держится в синхроне с `DSH_WEB_ADMINS` хоста).

Матрица прав:

| Действие | Обычный пользователь | Админ | Локальная/CLI |
|---|---|---|---|
| Видеть public + builtin + свои | да | да | да |
| Создавать/править/удалять свои | да | да | да* |
| Использовать шаблон (создать дек, редизайн своего проекта) | да | да | да |
| Импорт шаблона в public | нет | да | да |
| Правка меты/удаление public | нет | да | да |
| Публикация user → public | нет | да | да |
| Чужие личные шаблоны | нет | нет | нет |

\* CLI-сессия без owner работает с файлами шаблонов напрямую (см. §8) —
права библиотеки DSH к ней не применяются.

## 6. Инструменты (tool-плоскость)

### 6.1 Новый инструмент `ppt_template`

Операции (enum `operation`):

- `list` `{scope?}` — builtin + public + свои (у админа: + `scope: 'user:<login>'`);
- `get` `{templateId}` — манифест + список ассетов (без бинарников);
- `create-from-pptx` `{pptxPath, templateId, name, description?, overwrite?}` —
  импорт примера PPTX (см. §7.1) → сохранение шаблона;
- `create-from-project` `{deckPath, templateId, name, description?, overwrite?}` —
  проект → шаблон (см. §7.2);
- `save` `{templateId, manifest}` — создать/обновить личный шаблон
  (админ может указать `scope: 'public'`);
- `delete` `{templateId}`;
- `export` `{templateId, outputDir}` — записать bundle в рабочую папку сессии;
- `import` `{path | data(base64), scope}` — импорт bundle; `scope: 'public'`
  только для админа, иначе личный;
- `publish` `{templateId}` — админ: копия личного шаблона в public;
- `apply-to-project` `{deckPath, templateKey | bundlePath, expectedRevision?,
  saveAs?}` — **редизайн существующего проекта** (см. §7.5): меняет только
  оформление (theme, brand, фоны по типам страниц), контент и порядок страниц
  не трогаются; по умолчанию in-place с историей undo, `saveAs: true` —
  отдельной копией; записывает происхождение `template: {id, revision}`.

### 6.2 Изменения существующих

- `ppt_create`: новый параметр `templateId: string` (ключ библиотеки
  `<scope>:<id>`). Старый `template` (weekly/defense/project/pitch) не меняется —
  обратная совместимость схем и поведения.
- `editDeck` (движок): новый аргумент `theme` (валидация по THEME_IDS) рядом
  с существующим `brand` — база для редизайна; в схему `ppt_edit` не выносим,
  наружу редизайн идёт через `ppt_template apply-to-project`.
- `ppt_check`: показывает происхождение `template: {id, revision}` и незаполненные
  слоты (уже работает через `template-unfilled`).
- `config.ts`/`types.ts`: `admins: string[]`, лимиты шаблонов.

## 7. Движок шаблонов

Новый `skills/dsh-ppt/scripts/deck-templates.mjs` (общий для tool/CLI/панели,
как остальные deck-*.mjs):

### 7.1 `templateFromPptx(source, options)` — извлечение стиля

Через `@office-kit/pptx` (`loadPresentation` и Read-API, 0.21.0 — уже в зависимостях):

- `getPresentationTheme` + `getEffectiveColorMap` → палитра: primary/background/
  text (маппинг scheme-цветов dk1/lt1/accent1… на бренд dsh-ppt);
- `getPresentationFonts` → `fontFamily` (с проверкой на известные_safe-шрифты;
  редкий шрифт сохраняем, но помечаем предупреждение в манифест-отчёте);
- фоны: `getSlideMasterBackgroundImageBytes` / `getSlideLayoutBackgroundImageBytes`
  → выбираем самые используемые (обложка + контент), пишем в `assets/`;
- логотип: эвристика — небольшие повторяющиеся картинки на мастере/макетах
  (`getAllImages`, размеры/повторяемость) → `assets/logo.png`; иначе без логотипа;
- структура: `getSlideText` / `getSlideOutline` → заголовки слайдов → `outline`
  (layout по эвристике: первая страница → cover, последняя → closing, остальные
  → bullets/section);
- отчёт импорта: что извлечено, что нет (шрифты, которых нет в системе,
  отсутствие фонов) — возвращается в результате инструмента.
- Ограничения: PPTX ≤ 64 MiB; ассеты суммарно ≤ 8 MiB на шаблон; png/jpeg only.

### 7.2 `templateFromDeck(manifest, options)` — проект → шаблон

- стиль: текущие `theme` + `brand` манифеста проекта;
- каркас: слайды проекта → `outline` (тексты полей заменяются на плейсхолдеры
  «Заполнить: …», кроме заголовков-«разделителей», которые оставляем);
- образцы: до 3 слайдов как `samples` (по умолчанию включены, можно отключить).

### 7.3 `applyTemplate(templateKey | bundlePath, createArgs)`

- резолв шаблона (библиотека DSH или файл bundle);
- сборка аргументов `buildDeckAsync`: `theme`, `brand`, `slides` из outline+samples,
  `deliveryStatus` получится draft автоматически;
- запись `template: {id, revision}` в манифест проекта.

### 7.4 Bundle I/O

- `writeTemplateBundle(dir, template)` / `readTemplateBundle(zipOrJson)`:
  валидация `schemaVersion`, размеров, whitelist имён файлов (без `..`, без
  абсолютных путей, только `[A-Za-z0-9._-]`), mime ассетов, защита от zip-bomb
  (лимит распакованного размера), отсутствие symlink-записей.

### 7.5 `restyleDeck(deckPath, template, options)` — редизайн проекта

- резолв шаблона (ключ библиотеки или файл bundle);
- через `editDeck`: `theme: style.theme` (новый аргумент, §6.2) + `brand`
  (сливается по существующим правилам merge) + фоны (см. §7.6);
- контент, порядок и ID страниц не меняются; проверка `expectedRevision`;
- по умолчанию in-place: одна запись в историю undo (как coach-apply);
  `saveAs: true` — новая копия проекта;
- в манифест пишется `template: {id, revision}` (заменяя прежнее значение);
- возврат: что изменилось (тема, цвета, шрифт, логотип, футер, число фонов),
  предупреждения (шрифт отсутствует в системе, фон не поддержан целевым форматом).

### 7.6 Фоны слайдов (новая движковая возможность)

Сейчас у слайдов нет фонов-картинок (HTML — только палитра темы, PPTX —
заливки). Добавляем ограниченно и без влияния на существующие деки:

- манифест проекта: `style.backgrounds: [{layoutType, image(assetsRef), fit}]`,
  layoutType ∈ `cover | section | content | closing` (media-типы image/chart
  остаются без фонов);
- HTML (deck-core): фон слоя слайда через CSS `background-image` + `cover/contain`
  (текст поверх — контраст проверяется существующим `low-contrast`-чеком);
- PPTX (deck-advanced → `@office-kit/pptx`): `setSlideBackgroundImage` при
  экспорте;
- сквозь editDeck/create: фоны задаются только через шаблон (отдельный
  параметр наружу не вводится), чистятся при `template: null`;
- fallback: если целевой формат фон не поддерживает — дек собирается без фона,
  в отчёте инструмента и ppt_check появляется предупреждение.

## 8. CLI (build-deck.mjs)

- `--template-file <path.zip|json>` — создать дек из файла шаблона (вне DSH);
- `--restyle <deck.json> --template-file <path>` (или `--template-key <scope:id>`
  при доступной библиотеке) — редизайн готового проекта шаблоном;
  `--save-as` — отдельной копией;
- `--create-template-from-pptx <file.pptx> --save-template <dir>` — pptx → bundle;
- `--create-template-from-deck <deck.json> --save-template <dir>` — проект → bundle;
- `--list-templates` — сценарии + (если доступна библиотека DSH) шаблоны из
  `$DSH_HOME`; `--export-template <key> --to <dir>` — выгрузка из библиотеки.

## 9. Панель (workbench)

### 9.1 Серверные операции (`workbench.action`)

- `template-list` / `template-get` — библиотека с правами текущего owner;
- `template-create-from-project` — из проекта каталога (id → deckPath);
- `template-save` / `template-delete` / `template-publish` (403 без админа);
- `template-import` — загрузка zip/json base64 (лимит как у картинок, 12 MiB);
- `template-apply` `{templateKey, title}` — движок собирает дек в
  `templates/../created/<n>/`, регистрирует в projects.jsonl (через `remember`),
  возвращает id проекта → открывается штатный редактор;
- `template-restyle` `{projectId | deckPath, templateKey, expectedRevision,
  saveAs?}` — редизайн проекта из каталога выбранным шаблоном (§7.5); ответ
  содержит сводку изменений и предупреждения; после — штатный рендер/просмотр.
- `fetchDownload`: новый `kind=template` — скачивание bundle шаблона.

### 9.2 UI: новая вкладка «Шаблоны» (templates/panels/templates.js)

- сетка карточек: цветовой свотч стиля, имя, scope-бейдж (Встроенный /
  Общий / Мой), автор, дата, действия (Создать дек / Экспорт / Правка / Удалить);
- диалог шаблона: мета + палитра + каркас страниц (read-only превью списка);
- «Импорт шаблона» (файл): у всех — в личные; у админа переключатель «в общие»;
- «Редизайн шаблоном» — кнопка в редакторе проекта и в карточке библиотеки:
  выбор шаблона (сетка с свотчами) → сводка того, что изменится (тема, цвета,
  шрифт, логотип, фоны) → применение (по умолчанию in-place, галочка
  «сохранить как копию») → редактор показывает новую версию, undo доступен;
- админ-действия на общих: правка меты, удаление, публикация копии личного;
- кнопка «Сделать шаблон из проекта» в шапке библиотеки проектов;
- локализация zh/en/ru через существующий `t()` + словарь `client-ru.js`.

## 10. Безопасность

- Админ: fail-closed по модели §5; 403 на панели, отказ инструмента в CLI-плоскости
  с внятным сообщением.
- Импорт bundle: whitelist путей, лимиты (12 MiB upload / 64 MiB файл /
  8 MiB ассеты), mime png/jpeg, без symlink/`..`/абсолютных путей, zip-bomb guard.
- PPTX-импорт: только обычные файлы (`ordinaryFile`-аналог), путь из аргумента
  инструмента/сессии, никогда из браузера; панели — только загруженные байты во
  временном файле каталога данных.
- Панель: существующие origin/CSRF-проверки остаются; новые операции за той же
  проверкой `x-dsh-ppt-action`.
- Путь `$DSH_HOME` не доступен на запись браузеру напрямую — только через
  операции с валидацией.

## 14. Явно не делаем (v1)

- Историческое ограничение v1 «только стиль+структура» заменено в v3: геометрия поддерживаемых объектов сохраняется; точность произвольных контуров, эффектов, OLE и сложных диаграмм ограничена матрицей в docs/TEMPLATES.md;
- Пересборку структуры существующего дека по каркасу шаблона (restructure-режим
  редизайна): в v1 редизайн меняет только оформление; если нужна новая
  структура — «создать дек из шаблона» и перенос контента, v2 рассмотрит
  автоматический restructure с сохранением контента;
- Импорт шаблонов по URL и облачный каталог;
- Веб-редактор дизайна шаблона (правка меты и стиля — да, перерисовка фонов — нет);
- Синхронизацию шаблонов между машинами (только ручной экспорт/импорт bundle).
