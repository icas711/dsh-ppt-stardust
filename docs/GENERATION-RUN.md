# Экспериментальные режимы B/C и журнал

Этап 4 [плана](FEATURE-PLAN-COMPACT-GENERATION-2026-11-20.md). Изолированный модуль `skills/dsh-ppt/scripts/deck-generation-run.mjs` связывает brief, внешние реестры, профиль шаблона, модельный адаптер и существующую композицию. Production `ppt_create` и режим A не переключаются. CLI воспроизводит записанные ответы без сети и учётных данных провайдера.

## Режимы и лимит

Начиная с ru.40, runner версии 4 проверяет явные `planningConstraints` вызывающей стороны как на `scenario`, так и на `spec` B/C: число смысловых слайдов, purpose, а для spec — также visual.type. Оба режима получают инструкцию сохранять полный реестр в одной смысловой таблице; физические страницы рассчитывает движок. `spec-feasibility` требует полный исправленный spec для слияния/удаления плановых слайдов, не адресную замену старых ID. Общий бюджет исправлений не сбрасывается. Без переданных planningConstraints дополнительное ограничение не вводится. Старые записи runner 3 сохраняют исторические результаты; повторная проверка на runner 4 не становится новым живым опытом.

| Режим | Плановые запросы | Допустимые исправления | Максимум вызовов |
| --- | --- | --- | --- |
| B | spec | 2 на всё задание | 3 |
| C | scenario → spec | 2 суммарно, без сброса между стадиями | 4 |

Второй плановый запрос C не является исправлением: он превращает проверенный сценарий в spec. Невалидные JSON, нарушение контрактов, brief и замечания внешнего фактологического проверяющего расходуют общий бюджет. Неуспешный ответ на запрос исправления тоже расходует попытку. Внутренних повторов транспорта нет; адаптер не должен скрыто повторять модельные вызовы.

`generationScenarioSchema()` описывает `{version:1,slides:[{id,purpose,title,sourceRefs}]}`. Сценарий сохраняет порядок, назначение и источники слайдов без геометрии. Реестры поступают извне. Spec соответствует [generation-spec-v1](GENERATION-SPEC.md), языку/режиму данных вызывающей стороны и числу страниц brief. При `allowMoreSlides:true` можно увеличить количество; произвольное уменьшение запрещено. В C spec сохраняет IDs, purpose и порядок сценария; заголовки можно уточнить.

Ошибки привязываются к `code`, `path`, `slideId` (null при ошибке всего объекта), `message`. Если затронутые слайды однозначно определены, следующий запрос содержит только их содержимое, диагностику и соответствующие исходные фрагменты. Ответ имеет вид `{slides:[...]}` и заменяет строго указанные IDs. Остальные слайды сохраняются. Неверный формат такого ответа не расширяет область следующего исправления.

При ошибке уровня всего объекта, неразбираемом первом JSON или неоднозначных IDs требуется полный объект. Если в затронутых слайдах нет ни одной разрешимой ссылки и сценарий не помогает определить материал, передаётся полный внешний контекст; `sourceScope` явно фиксирует этот случай. Ссылка не доказывает достоверность факта. Ошибки композиции, шаблона и экспорта завершают запуск без запроса к модели на переписывание содержания.

## API

```javascript
import {runCompactGeneration} from './skills/dsh-ppt/scripts/deck-generation-run.mjs'

const result = await runCompactGeneration({
  mode: 'C',
  brief,                         // уже уточнённый brief v1
  context: {sources},            // внешние {id,text,synthetic?}
  template,                      // разрешённый bundle v3
  assets: {},                    // content-ассеты; ID определяются ключами
  dataMode: 'factual',            // переключить на demo может только вызывающая сторона
  complete: async (request, {signal}) => {
    // Единственный вызов модели; request содержит schema, instructions,
    // sources, ограничения и при необходимости current/diagnostics.
    return {text: savedText, model: 'recorded-model', usage: providerUsage}
  },
  onEvent: async event => persistEvent(event),
  reviewSpec: async (spec, registry) => [], // необязательная фактологическая проверка
  exportDeck: async (create, {signal}) => exportExistingEngine(create, signal),
  manualInterventions: [],       // сведения вызывающей стороны о ручных изменениях
  signal
})
```

`complete` возвращает `{text:string,usage?,model?,provider?}`. Markdown fences и комментарии не удаляются: ответ должен быть строгим JSON. `reviewSpec` возвращает массив диагностик `{severity:'error'|'warning'|'info',code,path,message,slideId?}`; ошибки запрашивают исправление. Сбой или неверный формат самого проверяющего завершает запуск как `review-error`. Предупреждения сохраняются в журнале. Без этого callback автоматической проверки полноты и истинности фактов нет.

До первого модельного запроса проверяются brief, соответствие templateId, реестр и пригодность шаблона. История реального `ask_user_question`, авторизация и роль вложений остаются ответственностью вызывающего контура. Модуль не выводит их из самодекларации модели.

`onEvent` вызывается последовательно и ожидается перед продолжением. Сбой записи пробрасывается вызывающей стороне и останавливает дальнейшие вызовы. Результат содержит тот же журнал в памяти; для долговременного хранения callback обязателен на стороне интеграции. Без callback журнал сохраняется только в возвращаемом объекте. Ошибки входных параметров происходят до запуска и выбрасываются как `generation-run-input`.

## Журнал и статусы

Записываются версии, brief, внешний контекст, профиль/preflight, ручные вмешательства, каждый точный запрос и ответ, модельные metadata/usage, время вызова, диагностика проверки, результат композиции, пути артефактов и финальный статус. У событий есть последовательный seq, UTC timestamp и elapsedMs. Ответы с ошибками и первоначальный текст сохраняются до проверки. Реестр не принимается из ответов модели.

Успешные технические статусы: `composed` и `exported`. Остановки: `budget-exhausted`, `provider-error`, `review-error`, `composition-error`, `export-error`, `cancelled`. Все результаты имеют `acceptance:'not-verified'`: техническая сборка не означает принятую презентацию. После отмены при экспорте пути уже созданных артефактов могут остаться в журнале.

Время runner начинается после preflight; импорт шаблона в CLI выполняется отдельно и этим временем не покрывается. Синтетическое воспроизведение не измеряет скорость модели. Usage сохраняется ровно как вернул адаптер; стоимость и биллинг по длине текста не вычисляются. Учет времени до пользовательской приёмки и сравнение A/B/C относятся к следующим этапам.

## Offline CLI

```powershell
node scripts/generation-run.mjs request.json responses.json .test-output/my-generation-run
node --test test/generation-run.test.mjs
```

`request.json`:

```json
{
  "mode": "B",
  "dataMode": "factual",
  "brief": {
    "version": 1,
    "goal": "Объяснить результаты",
    "audience": "Команда",
    "lang": "ru",
    "templateId": "my-template",
    "allowMoreSlides": false,
    "slideCount": 1,
    "attachments": [],
    "requiredFacts": ["Создано 30 видео"]
  },
  "context": {"sources": [{"id":"material-1","text":"Создано 30 видео"}]},
  "template": {"format":"zip","path":"my-template.zip"},
  "assets": {}
}
```

Путь шаблона разрешается относительно request.json; поддерживаются ZIP и PPTX через действующий импорт. `responses.json` имеет вид `{version:1,provenance?:string,responses:[{stage?:'scenario'|'spec',kind?:'initial'|'repair',text:string,usage?,model?,provider?}]}`. `text` содержит точный JSON-ответ модели как строку. Для воспроизведения ошибки транспорта допустима запись `{error:'message'}`. Необязательные stage/kind проверяют соответствие текущему запросу. Исчерпание записи — `provider-error`, не выдуманный ответ. Неиспользованные ответы явно подсчитываются.

CLI требует новую или пустую папку и сохраняет `request.json`, исходный `responses.json`, последовательный `journal.jsonl`, `result.json` и экспорт в `deck/`. При ошибке входа/импорта после открытия журнала добавляется `fatal`. Код завершения CLI равен 0 только при `exported`. Журнал и исходные материалы содержат данные задания: хранить их следует с теми же правами, что и входные файлы.

Проверки используют публичные синтетические записи из `test/fixtures/generation-recordings.json`, включая невалидные ответы. Живых результатов `glm-5.3-flash` этот набор не содержит. [Комплект независимых заданий A/B/C и новый оценщик](GENERATION-EVALUATION.md) добавлены на этапе 5; установка и живой пилот не выполняются этим CLI.
