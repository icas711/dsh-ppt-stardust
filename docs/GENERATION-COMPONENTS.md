# Компактный JSON → редактируемые слайды

Статус: экспериментальный этап 3 [плана](FEATURE-PLAN-COMPACT-GENERATION-2026-11-20.md). Работает без модели и не изменяет поведение production `ppt_create`. Оркестрация B/C, общий лимит исправлений и журнал добавлены отдельным модулем этапа 4: [GENERATION-RUN.md](GENERATION-RUN.md).

## Возможности

`deck-generation-compose.mjs` принимает spec v1, внешний контекст источников, разрешённый шаблон v3 и растровые ассеты. Возвращает `create` для существующего `buildDeckAsync`, lineage, диагностику и отчёт размещения.

| Тип | Редактируемые объекты / композиции |
| --- | --- |
| cards | Скруглённые фигуры, отдельные тексты и нативные иконки; ряд, сетка или вертикальный список |
| process | Круги, линии со стрелками, номера этапов и тексты; горизонтально или вертикально |
| timeline | Круги, связи, исходные даты и тексты; горизонтально или вертикально |
| comparison | Нативная таблица с общими критериями, альтернативами, неизвестными значениями и пояснениями |
| big_number | Один/два числовых акцента от 60 pt, единицы, подписи и детали; рядом или вертикально |
| chart | Нативная column/bar/line/pie с исходными сериями/значениями и единицами |
| table | Нативная таблица с расчётом ширины столбцов/высоты строк и повторением заголовков при разбиении |
| image | Исходное изображение с fit:contain, alt и необязательной подписью |

Каталог иконок: `check`, `clock`, `target`, `trend`. Иконки создаются нативными фигурами и линиями. В ответах модели нет координат или кода.

## Геометрия и оформление

Сохраняются размер, фон, фиксированный декор и референсы шаблона. Применяется извлечённая типографика, палитра и акцент. Неизвестные свойства дополняются явными компонентными значениями. Шрифты автоматически не уменьшаются ради вместимости.

Текст заголовка располагается по ориентиру шаблона. Учитываются правое/центральное выравнивание и исходные преобразования. Для преобразованного заголовка сохраняются его рамка/transform; если новый текст не помещается, возвращается ошибка.

Свободные прямоугольники вычисляются вычитанием рамок видимой фиксированной графики и заголовка. Для групп повторное преобразование детей не выполняется. Залитые прямоугольные плашки, содержащие исходные текстовые референсы, и почти полноэкранные фоновые прямоугольники рассматриваются как подложки. Это эвристика, не доказательство безопасности произвольной графики. Рассматривается ограниченное число крупнейших областей и несколько композиций.

Оценка строк учитывает размер шрифта, классы символов, ширину и межстрочный запас. Она не использует реальный шрифтовой движок; `report.fit` остаётся `estimated`, `visualAcceptance` — `not-verified`. Исходный стиль не перекрашивается автоматически для устранения предупреждений контраста. Для карточек со скруглёнными подложками существующая консервативная проверка может выдавать `contrast-unverified`.

## Переполнение

По умолчанию количество страниц не увеличивается. При `allowMoreSlides:true` после неудачи альтернативных композиций пробуется разбиение целых элементов/строк/критериев/категорий. Заголовки и исходные заметки сохраняются. Источники и диапазон продолжения записываются в заметки; отчёт связывает каждую страницу с исходным слайдом. Новые ID не конфликтуют с исходными.

Для сравнений повторяются альтернативы; для таблиц — заголовки. В категориальных column/bar диаграммах все серии разбиваются по одним и тем же категориям; единицы и значения сохраняются. Pie и line не делятся, чтобы не менять доли/целостную линию. Если даже единичный элемент не помещается, возвращается `component-capacity`; факты не удаляются. `maxSlides` ограничен диапазоном 1–120 и применяется также к результату разбиения.

Режим demo добавляет видимую маркировку синтетики на каждой странице, включая продолжения. Невозможность её разместить — ошибка вместимости.

## Ассеты и источники

Ссылки на факты связываются с внешним реестром; это не проверка истинности/полноты. Content-ассеты проверяются по фактическим байтам PNG/JPEG, размеру и метаданным. Конфликт ID content-ассета с ID шаблона блокируется.

Перед экспортом изображения получают обязательные для существующего движка ID `img-<sha256>`. Переназначаются ссылки слайдов, фонов и сохранённых sceneLayouts. Одинаковые изображения дедуплицируются. Понятные модели alias остаются в исходном spec.

## API

```javascript
import {composeGenerationSpec} from './skills/dsh-ppt/scripts/deck-generation-compose.mjs'
import {buildDeckAsync} from './skills/dsh-ppt/scripts/deck-advanced.mjs'

// template загружается вызывающей стороной после проверки доступа и роли вложения.
const result = composeGenerationSpec(spec, {
  template: {manifest, assets: templateAssets, report: importReport},
  context: {sources},
  assets: contentAssets,
  allowMoreSlides: true,
  maxSlides: 60,
  signal
})
const made = await buildDeckAsync({...result.create, outputDir})
```

Композиция сама не пишет файлы. Экспорт начинается только после успешной подготовки всех слайдов. `create.templateLineage` сохраняет происхождение шаблона. Проверка доступа и факт реального диалога `ask_user_question` остаются ответственностью вызывающего контура.

## CLI и демо

```powershell
node scripts/generation-components-demo.mjs .test-output/my-component-demo
node scripts/generation-compose.mjs request.json .test-output/my-output
```

Для демо нужен новый/пустой каталог. Создаются синтетические request.json, template.zip, отчёт и выходные файлы. Пользовательские вложения не используются. Демо строится тем же CLI, что принимает ручные JSON.

Request содержит `spec`, `context`, `assets`, `allowMoreSlides`, необязательный `maxSlides`, а также `template:{format:"zip",path:"template.zip"}`. Для явно выбранного PPTX: `template:{format:"pptx",path:"template.pptx",id:"corporate",name:"Corporate"}`. Относительный путь шаблона разрешается относительно request.json; каталог вывода — относительно текущей рабочей папки.

CLI не вызывает модель и не запрашивает согласование: он предназначен для уже уточнённого задания с явно назначенным шаблоном. Отчёт включает ограничения и замеры существующего экспорта. Наличие HTML/PPTX не подтверждает PDF: PDF зависит от доступного рендерера.

## Выполненные проверки

- 10 компонентных тестов: все типы, неизменность входов, светлый/тёмный и нестандартный размер, наследование шрифтов, плотные таблицы/категориальные диаграммы и точное сохранение данных при разбиении, неразбиваемые pie/line, лимит страниц, невместимый элемент, маркировка demo, строгие референсы/иконки/ассеты, обход большой фиксированной картинки.
- Реальный buildDeckAsync → HTML/PPTX: нативные диаграммы, таблицы, картинки, линии/фигуры и числовой акцент; презентация повторно открывается библиотекой и проходит её структурную проверку.
- Полный npm test со сборкой: 538 тестов, 536 passed, 2 skipped, 0 failed.
- Демо на 8 страниц отрендерено LibreOffice/WASM 0.2.3 и просмотрено по всем страницам. Явных обрезок и наложений в этом коротком наборе не обнаружено. Рендерер сообщил замены `Arial` и `Segoe UI`; идентичность исходным шрифтам/PowerPoint не подтверждена. Длинные произвольные данные и пользовательские шаблоны требуют самостоятельного расширенного прогона.

Локальные артефакты: `.test-output/generation-components-demo/`; исходные JSON/ZIP, HTML/PPTX, восемь PNG, overview.png и отчёты. В Git не включаются. Общий статус автоматического отчёта намеренно не повышен до визуальной приёмки произвольных результатов.
