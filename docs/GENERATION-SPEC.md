# Экспериментальный контракт генерации v1

Статус: первый этап [плана прототипа](FEATURE-PLAN-COMPACT-GENERATION-2026-11-20.md). Это проверка и промежуточное содержательное представление; автоматического размещения, вызовов модели и подключения к `ppt_create` пока нет.

## Получить JSON Schema

```powershell
node scripts/generation-spec.mjs schema
node scripts/generation-spec.mjs brief-schema
```

Источником обеих схем и runtime-проверки служит `skills/dsh-ppt/scripts/deck-generation-spec.mjs`. Проверка не исправляет данные и не преобразует типы.

## Пример ответа модели: spec.json

```json
{
  "version": 1,
  "title": "Результат пилота",
  "lang": "ru",
  "mode": "factual",
  "slides": [{
    "id": "slide-1",
    "purpose": "content",
    "title": "Создано 30 видеоуроков",
    "visual": {
      "type": "big_number",
      "sourceRefs": ["material:slide-1"],
      "items": [{"id": "videos", "label": "Обучающие видео", "value": 30, "unit": "видеоуроков"}]
    }
  }]
}
```

`sourceRefs` — обязательные ссылки визуала на внешние исходные фрагменты. Элемент может дополнительно указать собственные `sourceRefs`. Числа, текст, даты, связи и выбранные ссылки всё равно требуют проверки по исходному материалу. Проверка существования ссылки не доказывает корректность утверждения или полноту содержания.

## Контекст вызывающей стороны: context.json

```json
{
  "sources": [{"id": "material:slide-1", "text": "Сгенерировано 30 обучающих видео с участием аватара (полный закупочный цикл)"}],
  "assetIds": [],
  "iconIds": []
}
```

Контекст формируется из материалов/библиотек, не из ответа модели. Без реестра источников проверка блокируется. Неизвестные ссылки, изображения и иконки также блокируют преобразование. Поле `synthetic:true` у источника разрешено только при `mode:"demo"`. Промежуточный результат содержит `disclosures`; будущий компоновщик обязан вывести их на слайдах. Текущий этап ничего не рендерит.

## Проверить и преобразовать

```powershell
node scripts/generation-spec.mjs validate spec.json context.json
node scripts/generation-spec.mjs content spec.json context.json
node scripts/generation-spec.mjs validate-brief brief.json
```

CLI читает файлы, печатает JSON и возвращает ненулевой код при ошибке. Не записывает файлы и не вызывает модель. Для ошибки доступны `code`, `path`, `message`; для семантики/привязки визуала также `slideId`.

Преобразование сохраняет исходный visual и добавляет `diagram` для шести семантических типов. `big_number` с одним значением становится `number`, с двумя — `kpi`. Шесть типов используют существующую семантическую проверку. Таблицы и изображения остаются без геометрии до реализации компонентов. Иконки сохраняются в visual, существующая диаграмма их пока не рисует. Единица диаграммы сохраняется в visual и заголовке её семантических данных.

## Контракт brief

Обязательны `version:1`, `goal`, `audience`, `lang`, `templateId`, `allowMoreSlides`, `attachments`, `requiredFacts`; опционален `slideCount`. Каждое вложение имеет `id` и явно выбранный `role:content|style|both`. Пустой список вложений допустим.

Brief фиксирует ответы, но не подтверждает факт вызова `ask_user_question`. Исполнение этого требования проверяется по настоящему журналу DSH. JSON не является техническим разрешением на обход вопросов.

## Границы v1

- Языки: ru/en/zh. От 1 до 120 слайдов, без координат, произвольных цветов и стилей.
- Cards: 2–4 элемента; process: 3–5 с `ordered:true`; timeline: 2–6 с датами ISO и явным порядком.
- Comparison: 2–4 альтернативы, 1–8 общих критериев; неизвестное значение — `null`, без выдуманного заполнения.
- Big number: 1–2 конечных числа с единицами. Chart: column/bar/line/pie, 1–24 категории, 1–4 серии равной длины; line требует `ordered:true`, pie — `whole:true` и подходящих данных.
- Table: до 8 столбцов и 30 строк; ширина всех строк совпадает с заголовками; пропуск — `null`. Это предел входных данных, не обещание вместимости одного слайда.
- Image: существующий `assetId`, обязательный `alt`, необязательный `caption`.
- Вместимость, шрифты, графика шаблона, разбиение и визуальная приёмка — следующие этапы. Успешная проверка spec не означает успешного экспорта или принятого дизайна.
