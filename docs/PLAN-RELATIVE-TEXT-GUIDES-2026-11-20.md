# План: относительные ориентиры текста и импорт шаблонов из PPTX

Дата: 2026-11-20. Статус: реализовано, локальные проверки пройдены; серверная визуальная приёмка ожидается.

## 1. Цель

При свободной композиции модель получает относительное расположение текста, выравнивание, якоря и типографику. Размеры новых текстовых блоков, переносы и размещение относительно картинок и декора выбирает модель при подготовке слайдов.

Исходная рамка текста становится примером расположения, а не обязательным слотом. Для правого выравнивания сохраняется смысл правого якоря: ширина может меняться, левая граница сдвигается относительно выбранного правого края. Само выравнивание абзаца не фиксирует положение блока на странице.

Изменение касается текстовых ориентиров и инструкций свободной композиции. Декор, фоны и прочие объекты шаблона сохраняют исходную геометрию. Фактическая сцена по-прежнему содержит конкретные рамки в EMU: модель определяет их до вызова генератора.

Не вводить автоматический движок вёрстки, измерение каждого текста, переразмещение соседей, сокращение текста или обязательный цикл проверки/рендера. Относительные ориентиры помогают первоначальной композиции, но не гарантируют отсутствие переполнений и наложений.

## 2. Текущее состояние и заменяемое решение

В конце [прежнего плана](FIX-PLAN-INFERENCE-2026-11-20.md) зафиксировано копирование `x/y/w/h`, отступов и `autoFit:none` у заголовка. Для свободной композиции это требование заменяется настоящим планом. Исправление сохранности фоновых ассетов и выдача точных путей рендера остаются актуальными.

Сейчас `ppt_template get` показывает абсолютные `textRegions`, `decorRegions`, слоты и описания с оценками вместимости. Импорт `templateFromSceneManifest()` делает каждый содержательный текст обязательным слотом. Оба механизма направляют модель к воспроизведению исходных рамок даже для нового содержания.

Исходные рамки в хранилище нужны для редактора, превью и явного заполнения слотов. Удалять их из сохранённого шаблона не требуется.

## 3. Общий контракт относительных ориентиров

- [x] Добавить чистый модуль `skills/dsh-ppt/scripts/deck-template-guides.mjs`, строящий ориентиры из scene-макета и размера страницы без изменения исходных объектов, чтения файлов и вызовов модели.
- [x] Использовать общий расчёт для старых шаблонов и новых импортов. Сохранить `schemaVersion:3`; производные ориентиры не хранить как вторую независимую геометрию.
- [x] Позиции выражать в процентах страницы, обычный диапазон — 0–100. Не ограничивать значения принудительно: выход исходного объекта за страницу должен оставаться видимым.
- [x] Учитывать `transform` через существующие функции геометрии. Для повёрнутого/отражённого текста показывать признак преобразования; границы после преобразования не выдавать за точную область набора текста.
- [x] Установить единое округление, например до двух знаков после запятой. Расчёт использовать для подсказок, не для перезаписи исходных координат.

Предлагаемая структура `compositionGuides` на уровне макета:

```json
{
  "units": "percentOfPage",
  "text": [
    {
      "id": "heading",
      "name": "Heading",
      "alignment": "right",
      "anchor": { "horizontal": "right", "x": 94, "y": 5 },
      "referenceArea": { "left": 45, "top": 5, "width": 49, "height": 7 },
      "typography": {}
    }
  ],
  "decor": [
    {
      "id": "divider",
      "type": "shape",
      "referenceArea": { "left": 5, "top": 16, "width": 89, "height": 1 }
    }
  ]
}
```

Пример иллюстрирует форму данных. Поля `typography` использовать из существующего контракта стилей через `mergeSceneTextStyles()`, без переименования единиц и ключей.

- [x] Определить якорь как внешний край исходной рамки: слева для left, справа для right, центр для center. `y` — верхняя граница. Внутренние отступы не смешивать с координатой внешнего якоря.
- [x] Для неповёрнутого блока с правым якорем `R` модель выбирает ширину `W`, затем `x = R - W`. Пример в процентах: `R=94`, `W=40` даёт `x=54`; `W=55` даёт `x=39`. Правый край сохраняется при изменении ширины.
- [x] Для повёрнутого текста не применять эту формулу к видимому bounding box как к исходной рамке. Обозначить ограничение подсказки; фактическая сцена сохраняет собственные frame/transform.
- [x] `referenceArea` обозначить справочной областью образца. Не вводить обязательную ширину/высоту, лимит строк, `maxChars` или запрет выхода за эту область.
- [x] Передавать эффективную типографику первого содержательного run с учётом наследования и выравнивание абзаца. Не представлять это как полное описание всех смешанных стилей исходного текста.
- [x] Отступы и другие геометрические подсказки, если они нужны в кратком представлении, нормализовать по соответствующей оси страницы. Размер шрифта оставить в пунктах; единицы обозначить явно.
- [x] Передавать относительные границы декора для учёта моделью. Это не запрещённые зоны: текст поверх плашки или фона бывает частью дизайна. Фон страницы не превращать в препятствие на всю страницу.
- [x] Не передавать исходный текст, байты ассетов, полные массивы элементов и абсолютные матрицы в кратком представлении. Не угадывать назначение заголовка по содержимому при отсутствии достоверной роли; сохранить ID/имена и признаки оформления.

## 4. Ответ `ppt_template get`

Основной файл: `src/tools.ts`; при необходимости — контракт параметров и `src/execution.ts`.

- [x] Заменить стандартный текстовый вывод абсолютных `textRegions/decorRegions` на `compositionGuides`. Сохранить размер страницы, идентификаторы, имена, family/purpose, тему, бренд и `defaultReferences`.
- [x] По умолчанию не выводить массивы фиксированных слотов и описания с оценками вместимости, которые модель может принять за ограничения свободной композиции.
- [x] Добавить явный параметр `includeFixedSlots:true` для получения исходных рамок, слотов и полных описаний при работе с фиксированным заполнением. Описать его в схеме инструмента.
- [x] Сохранить полный manifest в существующем результате исполнения и API редактора. Новый параметр управляет представлением для модели, не удаляет данные из хранилища.
- [x] В коротком пояснении указать: ориентиры справочные, модель выбирает размеры и переносы и учитывает картинки/декор до генерации. Для right пояснить связь якоря и изменяемой ширины.
- [x] Сохранить выбор референсов: явный `designLayout` имеет приоритет; далее точный purpose; fallback в content только для не-cover. Новый механизм не выбирает титульный дизайн автоматически по порядку макетов.
- [x] Проверить сокращение объёма ответа без дублирования одной геометрии в нескольких форматах. Данные шаблона оставить явно отделёнными от инструкций инструмента.

Основные функции: `templateFromSceneManifest()` и `templateFromPptxScene()` в `skills/dsh-ppt/scripts/deck-templates.mjs`. Нормализация/заполнение: `deck-template-scene.mjs`; описание вариантов: `deck-generation.mjs`.

- [x] Для новых scene-шаблонов создавать текстовые слоты с `required:false`. Сохранить slotId/elementId и исходные рамки как совместимый путь явного заполнения.
- [x] Применить правило к импорту PPTX через scene-модель и к созданию шаблона из scene-проекта. Проверить реальные точки входа редактора, чтобы изменение не осталось только в отдельной функции.
- [x] Не менять автоматически обязательность изображений, таблиц и диаграмм. Legacy-импорт оставить с прежним контрактом; явно указать область действия изменения в документации.
- [x] Продолжить очистку исходного содержательного текста в шаблоне. При свободной композиции placeholders не должны переноситься на итоговый слайд или требовать заполнения каждого исходного блока.
- [x] Согласовать `slots.required`, нормализованное `description` и его производную ревизию. Описание нового шаблона вычислять после изменения обязательности.
- [x] Сохранить декор, фоновые ассеты всех макетов, стили, порядок объектов, трансформации, шрифты и связи с ассетами. Не назначать purpose:cover только по номеру исходного слайда.
- [x] В отчёте импорта кратко указать, что текстовые области доступны как ориентиры и как необязательные фиксированные слоты. Не дублировать полный набор ориентиров, доступный через get.
- [x] Не пересохранять массово старые шаблоны. Они получают относительные ориентиры при чтении; сохранённые required и поведение явного заполнения остаются прежними.

`required:false` само по себе не освобождает композицию от рамок и не удаляет placeholders. Изменение импорта должно сопровождаться новым видимым контрактом и проверкой пути свободной композиции.

## 7. Совместимость и пограничные случаи

- [x] Старый schemaVersion:3 загружается без миграции; get строит ориентиры на лету.
- [x] Явное заполнение слотов сохраняет рамки, выравнивание и ранее заданную обязательность. Оно не начинает свободно перекомпоновывать текст.
- [x] Создание проекта, редактирование, undo и применение шаблона не теряют фоновые ассеты и исходные элементы из-за нового представления метаданных.
- [x] Отдельно проверить `apply-to-project`: определить, использует ли он свободную композицию или фиксированные слоты, и сохранить заявленную семантику. Не распространять изменение молча на все режимы редизайна.
- [x] Поддержать отсутствие текстовых областей, пустые абзацы, разные align, нестандартные страницы и трансформированные группы. Не подставлять 16:9 при наличии реального размера.

## 8. Локальные проверки

Тесты проверяют контракт и сохранность данных. Они не доказывают качество композиции конкретной модели.

- [x] Построитель: left/right/center, проценты, размер страницы, округление, transforms, отсутствие мутации источника и исходного текста в выдаче.
- [x] Реальный `output.render` инструмента get: краткие ориентиры видимы модели; абсолютные слоты доступны по явному запросу; ID/purpose/defaultReferences сохранены.
- [x] Заменить регрессию «две строки обязаны иметь одинаковую рамку» на «две выбранные ширины сохраняют общий правый якорь». В экспортированном PPTX проверить разные рамки, общий правый край и `algn:r`. Это проверка возможности, а не подбор ширины по длине строки.
- [x] Реальный PPTX → scene-шаблон: текстовые слоты необязательны, исходный текст очищен, геометрия/декор/фон/шрифты сохранены, get выдаёт относительные ориентиры.
- [x] Scene-проект → шаблон: то же правило слотов, объявленные purpose сохранены, исходный проект не изменён.
- [x] Старый шаблон с required:true: get работает, явное заполнение сохраняет поведение. Новый шаблон также позволяет заполнить конкретный слот по ID.
- [x] Свободная композиция: количество и размеры новых текстовых блоков могут отличаться от образца, placeholders отсутствуют, декор на месте. Обязательность изображений/таблиц/диаграмм не меняется случайно.
- [x] Сохранить регрессии фоновых ассетов, истории/undo, путей рендера, ревизий и выбора референсов.
- [x] После профильных проверок выполнить `npm test` и принятую сборку. Обновить поставляемые `lib/tools.js` и `lib/client.js`, если сборка их меняет. Повторять проверки при новых изменениях или сбоях.
