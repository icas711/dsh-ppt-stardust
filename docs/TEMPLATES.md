# Библиотека шаблонов dsh-ppt

При обычной генерации шаблон задаёт оформление: размер страницы, фон, логотипы, шрифты и палитру. Модель свободно размещает новый контент. Титульной и одной контентной страницы достаточно; дополнительные варианты структуры не обязательны. Фиксированные слоты и каркас сохраняются для совместимости и специальных задач заполнения; незаполненный каркас остаётся черновиком.

Перед каждой новой генерацией обязательно: **используй ask_user_question и задавай вопросы пока задача не будет ясна**. Нужно дождаться ответа, подтвердить даже уже указанный шаблон и уточнить контент. Если шаблонов нет, согласовать стиль и использовать `brand + slides`. Если инструмент недоступен или ответа нет, генерацию не начинать. Это обязательная инструкция; техническая проверка фактических вызовов на стороне DSH пока не реализована и 100% исполнения не подтверждены.

## Скоупы и права

| Ключ | Где лежит | Кто видит | Кто управляет |
|---|---|---|---|
| `builtin:<id>` | пакет плагина (`assets/templates/`) | все | никого (read-only) |
| `public:<id>` | `$DSH_HOME/plugins/dsh-ppt/templates/public/` | все | админ |
| `user:<id>` | `$DSH_HOME/plugins/dsh-ppt/templates/users/<логин>/` | только владелец | владелец |

**Админ** (модель плагина auto-memory): авторитетный ответ `webAuth` хоста
(флаг `admin` в cookie-идентичности для панели, `isAdmin` для инструментов);
если хост недоступен — запасной список `admins` в конфиге плагина
(сравнение trim, регистрозависимое). Сессия без owner (локальная/CLI) —
админ; делегированная сессия (fork/fleet) — никогда не админ; всё
сомнительное — не админ (fail-closed). Публикация личного шаблона в общие и
импорт в общие — только админ (`owner` — чей шаблон публикуется).

## Формат bundle

`dsh-ppt-template v1` = ZIP:

```
template.json    # манифест (schemaVersion 1, ≤ 1 MiB)
assets/*         # PNG/JPEG: логотип, фоны (≤ 5 MiB каждый, ≤ 8 MiB суммарно)
README.txt
```

Принимается и голый `template.json`. Защита: whitelist имён файлов, mime
png/jpeg, лимит распаковки 16 MiB, без `..`/симлинк.

## Инструменты

### Создание презентации из шаблона

```
ppt_create { title, templateId: "builtin:corporate-report", lang: "ru" }
```

`templateSamples: false` — без слайдов-образцов. Сценарные `template`
(weekly/defense/project/pitch) работают как раньше.

### Шаблон из примера PPTX / из проекта

```
ppt_template { operation: "create-from-pptx", pptxPath, newTemplateId, name }
ppt_template { operation: "create-from-project", deckPath, newTemplateId, name }
```

Из PPTX извлекается стиль (палитра темы, шрифты, фоны мастеров/макетов,
логотип-эвристика по маленьким картинкам мастера) и каркас заголовков.
Геометрия слайдов не копируется — новые деки рендерит движок dsh-ppt.
В отчёте (`report`) перечислено, что извлечено и предупреждения (нет логотипа,
нестандартный шрифт).

### Импорт / экспорт

```
ppt_template { operation: "import", path | data, scope: "user" | "public" }
ppt_template { operation: "export", templateId, outputDir }
```

`scope: "public"` — только админ. Панель: «Презентации» → переключатель
«Шаблоны» → «Импорт шаблона» (файл до 9 MiB), кнопка «Экспорт» на карточке
(скачивание ZIP).

### Панель: шаблоны внутри «Презентаций»

Отдельного пункта «Шаблоны» в сайдбаре нет. На экране списка проектов
(«Презентации») есть переключатель **Проекты | Шаблоны**; внутри открытого
проекта по-прежнему работает «Редизайн шаблоном» (меняется только оформление,
тексты и порядок страниц не трогаются).

Вкладка «Шаблоны»: карточки (встроенные / общие / личные), «Новый шаблон»,
«Импорт шаблона», «Шаблон из проекта», на карточке — «Создать дек», «Править»
(«Открыть» для чтения), «Дублировать», «Экспорт»; админу ещё «Опубликовать»,
«Сбросить к встроенному» и удаление общих.

Редактор шаблона (разделы «Основное / Стиль / Каркас / Образцы»):

- основное: id (только при создании), название, описание;
- стиль: базовая тема, основной цвет / фон / цвет текста (пусто — цвет темы),
  шрифт, название бренда, футер, логотип, фоны для обложки / раздела /
  контента / финала с режимом вписывания;
- каркас и образцы: страницы шаблона (тип, надзаголовок, заголовок,
  подзаголовок, пункты, заметки), порядок, дублирование, удаление; образцов до 5;
- живое превью справа: мини-дек из пяти страниц (обложка, раздел, список,
  тезис, финал) в стиле черновика, обновляется при каждой правке и ничего не
  сохраняет (`template-preview`, HTML-движок без сборки PPTX).

Права и перекрытие встроенных:

- личный шаблон правит его автор;
- общий и встроенный правит только админ; обычному пользователю шаблон
  открывается для чтения, «Сохранить как копию…» кладёт правки в личные;
- админ, сохранивший встроенный шаблон, создаёт **общую копию с тем же id**
  (ревизия продолжается: встроенная + 1). Она перекрывает встроенный для всех
  пользователей: в списке показывается только копия (метка «заменяет
  встроенный»), ключ `builtin:<id>` в apply / restyle ведёт на неё.
  «Сбросить к встроенному» удаляет копию и возвращает оригинал;
- сохранение защищено от гонок: если шаблон изменили после открытия
  редактора, сервер отклонит запись (`expectedRevision`).

Операции панели (`POST /api/dsh-ppt/workbench`): `template-list` (+ список тем),
`template-get` (+ права и данные картинок), `template-save` (манифест + только
новые файлы `uploads`, неизменённые берутся из `baseKey`), `template-preview`,
`template-duplicate`, `template-create-from-project` (проект по id каталога,
путь из браузера не принимается), `template-import`, `template-apply`,
`template-publish`, `template-delete`.

### Редизайн существующего проекта

```
ppt_template { operation: "apply-to-project", deckPath, templateId | bundlePath,
               expectedRevision, saveAs }
```

Меняется только оформление (theme, brand, фоны по типам страниц
cover/section/content/closing); текст и порядок страниц не трогаются.
По умолчанию правка in-place и попадает в историю undo; `saveAs: true` —
отдельная копия. В манифест проекта пишется происхождение
`template: {id, revision}`, видимое в `ppt_check`.

Панель: кнопка «Редизайн шаблоном» в инспекторе открытого проекта.

### Прочее

```
ppt_template { operation: "list" | "get" | "save" | "delete" | "publish" }
```

## CLI (автономный skill)

```
node build-deck.mjs --title "Отчёт" --template-file corp.zip            # создать из шаблона
node build-deck.mjs --restyle deck.json --template-file corp.zip        # редизайн
node build-deck.mjs --create-template-from-pptx example.pptx \
  --template-id corp --template-name "Corp" --save-template .           # pptx → шаблон
node build-deck.mjs --create-template-from-deck deck.json \
  --template-id corp --template-name "Corp" --save-template .           # проект → шаблон
node build-deck.mjs --export-template public:corp --to ./out            # выгрузка (DSH-библиотека)
```

`--template-key <scope:id>` вместо `--template-file` берёт шаблон из
библиотеки DSH (`DSH_HOME`, для личных — `DSH_USER`).

## Макеты с картинками (schemaVersion 2)

Шаблон может хранить набор **макетов** `style.layouts[]`: у каждого свой фон и список картинок с положением и размером. Координаты `x`, `y`, `w`, `h` — проценты слайда (0–100; левый верхний угол и размер), поэтому не зависят от формата исходного слайда.

```json
{ "id": "cover-1", "name": "Титульный слайд", "layoutType": "cover",
  "background": { "image": "img-ab12cd34.jpg", "fit": "cover" },
  "backgroundColor": "#FFFFFF",
  "images": [ { "image": "logo.png", "svg": "logo.svg", "x": 4, "y": 6, "w": 18, "h": 9,
                "z": 0, "fit": "contain", "role": "logo" } ] }
```

- `layoutType` — `cover | section | content | closing`; `role` — `logo | header | decor | background | photo`; `fit` картинки — `contain | cover | fill`. До 120 вариантов макетов, до 12 картинок на макет.
- Слайд каркаса выбирает макет полем `layoutId`; без него берётся первый макет нужного типа страницы. Шаблоны без `layouts` (schemaVersion 1) работают как раньше: фоны по типам и логотип.
- Картинки лежат под текстом, порядок — по `z`. **HTML-плеер** показывает SVG (если есть), **экспорт PPTX** кладёт PNG/JPEG в те же позиции (фон макета — на весь слайд, ниже текста).
- SVG — только безопасный: без скриптов, `foreignObject`, внешних ссылок и DTD, до 300 КиБ. Иначе импорт оставляет PNG и пишет предупреждение.
- Проект с макетами при «Шаблон из проекта» переносит их вместе с файлами.

### Импорт из PPTX с диска

Панель: «Презентации» → «Шаблоны» → «Шаблон из PPTX». Файл до 64 MiB уходит на сервер сырым телом (`POST api/dsh-ppt/template-upload`, параметры `templateId`, `name`, `scope`, `lang`).

- Анализируются только существующие слайды и используемые ими мастера/макеты. Неиспользуемые внутренние макеты не импортируются.
- Общее оформление объединяется полем `familyId`; структура контента и типографика определяют варианты. Одинаковые варианты переиспользуются через `layoutId`. Мелкие различия положения декора (до округления координат к целому проценту) допускаются внутри одной группы, при этом точная геометрия каждого варианта сохраняется.
- Сохраняются фоны, логотипы, группы картинок, поддерживаемый декор и SVG-пары. Картинка слайда считается логотипом по имени (`logo`, «логотип», «эмблема») либо небольшой рамке у верхнего/нижнего края; остальные картинки слайда заменяются областями `image`. Это эвристика: результат следует просмотреть в редакторе.
- Заголовки, текст и содержательные изображения заменяются областями нового контента `textZones` (`title`, `body`, `image`). Сохраняются разные колонки и их положение. До 6 областей в варианте; превышение отражается в отчёте. Если контентная страница содержит только заголовок, добавляется область текста ниже шапки. Редактор позволяет менять каждую область отдельно.
- Каждая область хранит собственные `textStyle` и `textFrame`: эффективный размер/начертание, шрифт, выравнивание абзаца, вертикальную привязку, внутренние отступы в EMU, интервалы и унаследованный автоподбор. `colorSpec` хранит базовый RGB и преобразования цвета для точного вывода PowerPoint; `fontHints`, `scriptFonts`, `sourceTypeface` и `style.themeFonts` сохраняют параметры подстановки и исходные записи шрифтовой схемы, включая значимые для PowerPoint пробелы в имени. Стиль области имеет приоритет над общими стилями ролей. Редактор, ZIP и повторный экспорт сохраняют эти поля.
- `style.pageSize: { width, height }` хранит точные размеры в EMU. Они сохраняются в ZIP, редакторе, проекте, HTML-предпросмотре, печати и PPTX. A4, портретные и произвольные размеры не адаптируются к 16:9. Старые шаблоны без этого поля используют прежний формат 16:9.
- Отчёт содержит число групп оформления и вариантов, исходные размеры, статистику картинок и список `skippedObjects`: имя/тип, источник (слайд, макет или образец), затронутые слайды и причину. Повторы объектов общего мастера объединяются. Старое поле `skippedShapes` сохраняется для совместимости.
- Неподдерживаемые фигуры и статический текст оформления, требующий ручного переноса, перечисляются в отчёте. Автоматические поля номера, даты и колонтитула не переносятся. Содержимое исходных заголовков и текста не попадает в каркас.
- Крупные растры (> 700 КиБ или > 2560 px) сжимаются на сервере (`jpeg-js`, `pngjs`). Одинаковые изображения хранятся один раз.

## Фоны страниц

Фоны из шаблона применяются по типу страницы: в HTML — CSS-слой
(`data-bgt`), в PPTX — `setSlideBackgroundImage`. Дека без фонов полностью
работоспособна; неподдерживаемый формат собирается без фона с предупреждением.
Движковые ограничения: `style.backgrounds` задаётся только через шаблон.

## Шаблоны v3 и объектные слайды

Импорт через `ppt_template create-from-pptx`, панель и CLI создаёт шаблон schemaVersion 3. Совместимый низкоуровневый `templateFromPptx` сохраняет прежний режим без опций; для нового пути укажите `{ model: 'scene' }` или вызовите `templateFromPptxScene`. Шаблоны v1/v2 продолжают читаться.

Макеты v3 содержат `elements` и `slots`, объединяются по оформлению в семейства и сохраняют варианты структуры существующих слайдов. Геометрия хранится в EMU, физический размер страницы берётся из PPTX. Неиспользуемые внутренние макеты не импортируются; преобразования печатных форматов в 16:9 нет. Текст содержит отдельные абзацы, фрагменты и разрывы; поддерживаются жирность, курсив, подчёркивание, цвет с преобразованиями, параметры исходного шрифта и выравнивание. Изображения фона сохраняются отдельными фонами, не подменяют редактируемое содержимое.

Для заполнения получите ID вариантов и областей через `ppt_template get`, затем передайте `templateSelections: [{ layoutId, values: { slotId: value } }]` в `ppt_create`. Текст принимает строку или абзацы; изображение — ID внедрённого PNG/JPEG; таблица или диаграмма — типизированный объект. Новые изображения передаются в `assets` или загружаются в инспекторе объектов. Пропущенные обязательные области остаются помеченным черновиком. Исходные содержательные тексты и числовые примеры заменяются заготовками; оформление и логотипы сохраняются. Автоматическую классификацию можно исправить в редакторе.

Проекты с объектами имеют schemaVersion 2 и `layout:scene`. Инспектор позволяет выбирать объект, менять фрагменты текста и их оформление, положение, роль, данные диаграмм и содержимое ячеек. Сохранение, история, копирование, удаление, перестановка слайдов и undo поддерживают объекты. При перезагрузке с сохранением ввода независимые изменения объектов объединяются, конфликты показываются для проверки. Старый ввод по-прежнему допустим; `ppt_edit convertToScene:true` явно преобразует проект и всю историю атомарно. Ошибка в любом снимке оставляет исходные файлы нетронутыми.

При редизайне на v3 выберите вариант; инструменты принимают `layoutMap: { slideId: layoutId }`. Совпадающие области связываются по ID. Несопоставленный контент сохраняется с предупреждением о размещении, а не исчезает. Панель позволяет явно выбрать один вариант для всего дека.

## Матрица поддержки и ограничения

| Объекты | Реализовано | Ограничения |
|---|---|---|
| Текст | Независимые блоки, абзацы, фрагменты, разрывы, основные стили, поля с кешированным значением, метаданные шрифта | Автонумерация, нестандартные маркеры, вертикальный/RTL-текст и явные коэффициенты автоподбора требуют дальнейшего импорта; отказ сопровождается причиной |
| Геометрия | Исходные EMU, порядок слоёв, вложенные группы, масштаб, поворот и отражение | Сдвиг осей (shear), произвольные контуры, сложные заливки и эффекты не объявлены точным нативным переносом |
| Изображения | PNG/JPEG, обрезка, способы заполнения, фон, дедупликация | EMF/WMF/SVG и прочие форматы требуют отдельного преобразования; весь слайд в картинку не превращается |
| Диаграммы | Несколько нативных column/bar/line/pie/doughnut/area, поддерживаемые stacked/percentStacked, данные и встроенная Excel-книга | Кеши категорий/значений должны согласовываться; сложные оси и специальные типы проверяются отдельно. HTML сохраняет данные, но не гарантирует совпадение вёрстки Office |
| Таблицы | Размеры строк/колонок, текст, заливки, границы и объединения rowSpan/colSpan | Сложные наследуемые стили требуют дополнительной матрицы; интерфейс редактирует содержимое ячеек, структурные объединения задаются через модель |
| OLE и неизвестные объекты | Проверенное PNG/JPEG-превью, если доступно, иначе явная диагностика со слайдом, ID, именем и причиной | Вложения не запускаются и не переносятся в ZIP шаблона или новый генерируемый PPTX. Наличие превью не означает редактируемость исходного объекта |

Лимиты новой модели: 256 объектов и 128 размещений изображений на слайд (включая фон/превью), глубина групп 16, 8192 объекта на проект/шаблон, 120 слайдов/вариантов. Фигуры и линии не расходуют бюджет изображений. Таблица: до 32 колонок × 100 строк; диаграмма: до 256 категорий и 32 серий. PNG/JPEG — до 5 МиБ; изображения шаблона — суммарно 8 МиБ, проекта — 32 МиБ. Шрифт — до 12 МиБ, суммарно 32 МиБ. Манифест шаблона — 1 МиБ, JSON проекта с историей — 64 МиБ; ZIP и распакованный импорт — до 64 МиБ. Превышение даёт ошибку, не скрытое обрезание. Прежние лимиты 6 областей / 12 картинок остаются только в совместимом пути v1/v2.

Привязанные `dataModel` проекты продолжают работать в прежней схеме. Их преобразование в scene блокируется до реализации адресных привязок; данные не замораживаются в обычный текст. ИИ-репетиция читает содержимое объектов, но её текстовые правки применяются вручную в инспекторе. Визуальные исправления адресуют объект по `elementId`; разрешены ограниченные изменения размера текста, подписей диаграммы, направления столбцов и заполнения изображения.

Для списков есть карточки, процессы, сравнения по общим критериям, иерархии, связи, временные шкалы, циклы, KPI, цитата и крупное число через `layout:diagram`. Новый семантический ввод использует `version:2`. Числовая диаграмма требует настоящих категорий и значений. Схемы состоят из редактируемых фигур, текста и линий; SmartArt не генерируется. Процесс, шкала, цикл и связи ограничены 6 узлами, KPI — 6 показателями, сравнение — 2–4 альтернативами и 1–8 критериями; карточки и иерархия — 12 пунктами. Более длинный источник нужно явно разбить, сохранив содержимое.

Приёмка зависит от сценария. Генератор и редактор проверяются по сохранности содержания/данных, читаемости, вписыванию, подходящей структуре и редактируемости; сравнение новой презентации с чужим исходником по SSIM не требуется. Для импорта шаблона обязательны исходный размер страницы, оформление/логотипы и области в заявленной поддержке, заполнение новым содержимым и отчёт о потерях; SSIM служит диагностикой вместе с визуальной проверкой проверенных примеров. Синтетические поддерживаемые классы по-прежнему проходят строгий SSIM ≥ 0,999.

Рабочий шестислайдовый файл пока не проходит benchmark точной копии: остаются неподдерживаемые объекты и отличия диаграмм. Это не общий блокирующий критерий выпуска и не разрешение игнорировать потерянное содержимое или неверные данные. Его импорт не следует выдавать за точную копию. Исторические критерии импорта — [раздел 6.0 прежнего плана](archive/FEATURE-PLAN-SLIDE-MODEL-2026-11-19-before-simplification.md#60-критерии-выпуска-по-сценариям); фактические результаты — [отчёт приёмки](validation/SCENE-ACCEPTANCE-2026-11-19.md).

Импорт по URL, облачный каталог и синхронизация между машинами не добавлены; библиотека переносится экспортом bundle.

Отдельно согласован [контракт будущего режима патча](PPTX-PATCH-CONTRACT.md): исходные разрешённые OLE остаются непрозрачными внутри пользовательского PPTX с проверкой побайтовой неизменности и отчётом; обычные гиперссылки разрешены, VBA/остальные внешние связи и части вне явного allowlist отклоняются. Это планируемый дополнительный путь, а не действующая команда шаблонов; разрешение не распространяется на библиотеку ассетов, ZIP шаблона и новую генерацию. Реализация будет согласована отдельно.

## Свободная композиция в шаблоне v3

После обязательных вопросов и ответа пользователя получите оформление через `ppt_template get`. Передайте `ppt_create {title,templateId,slides:[{layout:'scene',purpose:'content',elements:[...]}]}`. Для титульного слайда укажите `purpose:'cover'`. По умолчанию выбирается образец того же назначения; раздел/финал могут использовать контентный образец, если специального нет. `designLayout` позволяет явно выбрать существующий образец. Движок переносит фон и объекты `role:'decor'`, исключает образцы контента и наследует типографику: первый текст — заголовок, последующие — основной текст. Явные стили имеют приоритет. Новые объекты задаются в порядке наложения, геометрия — в целых EMU.

Фигуры: `rect`, `roundRect`, `ellipse`, `triangle`, `diamond`, заливка и обводка; подписи добавляются отдельным текстом. Доступны линии, группы, изображения, таблицы и поддерживаемые диаграммы. Несколько независимых блоков на одном слайде допустимы и ожидаемы, когда это помогает объяснить материал. Слоты и их ёмкость не ограничивают свободный путь. Не смешивайте scene `slides` с `deckPlan`/`templateSelections`.

## Совместимый путь фиксированных слотов и вариантов

Следующий контракт остаётся для старых проектов и явного заполнения фиксированных областей. Он не является обязательным для обычной генерации; дальнейшее развитие редактора вариантов и правил ритма приостановлено.

Варианты v3 получают `description.version:1`: назначение, подходящее содержимое, ограничения, частоту, допустимые структуры и описание каждой области. Ёмкость, заданная пользователем, — жёсткое ограничение; автоматическая оценка текста — подсказка. При смене геометрии/шрифта оценка пересчитывается. Описание не дублирует геометрию. Старые v3 ZIP читаются с автоматически построенным описанием; общий модуль нормализации используется сервером и собранным клиентом.

Для явного заполнения фиксированных слотов получите варианты через `ppt_template get`, составьте `deckPlan` и проверьте его через `ppt_template operation:'validate-plan'`. Передайте тот же план в `ppt_create` с `templateId`. Строка плана содержит `id`, `variantId`, `intent`, `structure`, `values` по ID областей; необязательные `sources`, `evidence` и `visual:{slotId,diagram}` задают семантические основания. `visual` создаёт нативные объекты внутри совместимой независимой текстовой области, сохраняя размер страницы, оформление и соседние объекты. Группированная или повёрнутая область для автоматической раскладки отклоняется. План несовместим с одновременными `content`, `slides`, `templateSelections` и `dataModel`.

Проверка выдаёт ошибки типов/данных/жёсткой ёмкости и предупреждения об оценке вписывания и ритме. Альтернативы содержат явное сопоставление областей; содержимое само не перемещается. Начальная `generationPolicy` v1: проверять от 6 содержательных слайдов, предупреждать о серии более двух одинаковых вариантов/структур и более одного акцента в окне пяти. Политика настраивается. Структурная сигнатура игнорирует текст, изображения и косметику. Отчёт хранит использованные варианты/структуры, неиспользованные варианты и диагностику; после правок помечается устаревшим, undo восстанавливает его состояние.

Редактор позволяет дублировать вариант, отражать расположение областей, создавать 1–4 колонки, варианты с изображением слева/справа или без него; менять назначение, роли, типы областей и ёмкость. Есть предупреждения о структурных дубликатах, undo, короткие/длинные образцы и сохранение ZIP. Новый вариант изображения использует явную нейтральную заготовку для последующей загрузки. Автоматическая перестановка групп, связанных и повёрнутых объектов ограничена; обычное дублирование сохраняет группы. Результат перестановки требует просмотра.

Проверка переполнения в iframe измеряет HTML после загрузки шрифтов и показывается отдельно от эвристической оценки. Она не гарантирует вписывание экспортированного PPTX. Шрифт скрыто не уменьшается. Явные команды возврата к списку/перестроения визуальной структуры сохраняют источник и имеют undo; ручная геометрия при перестроении может измениться. Полный исходный текст и форматирование сохраняются, включая жирность, цвет и выравнивание.

Подтверждены восемь вариантов нативных диаграмм: column, bar, line, pie, doughnut, area, stacked-column и percent-stacked-bar. Выбор доступен в инспекторе и сохраняет числовые данные; недопустимое преобразование отклоняется. Scatter не включён. [Локальные проверки и ограничения](validation/DECK-GENERATION-2026-11-19.md).

После пользовательского прогона добавлена проверка контраста фактических текстов/фрагментов scene и ячеек таблиц. Предупреждение указывает объект и отношение цветов; фон с изображением, частичным перекрытием или преобразованиями цвета отмечается как `contrast-unverified`. Это статическая проверка сплошных цветов, не сертификация всех объектов/нативных chart labels. Автоматического перекрашивания пользовательского шаблона нет.

`get` теперь выводит описания v3 в текстовом ответе инструмента; `create/check` показывают отчёт плана отдельно от качества вёрстки и отмечают устаревание после правок. `generationPolicy.minSlides` — порог включения ритма: один слайд разрешён с политикой по умолчанию. Перед каждой новой генерацией уже указанный templateId всё равно подтверждается через `ask_user_question`; при пустой библиотеке через этот же инструмент согласуется стиль.

Новые семантические диаграммы v2 получают оформление шаблона и заголовок из имени единственной серии. Небольшие наборы до 12 категорий/4 серий получают подписи значений, кроме area; в больших наборах подписи включаются явно после проверки. Явные настройки имеют приоритет. У pie различаются цвета сегментов; внутри doughnut/накопленных столбцов цвет подписи подбирается по заливке. Палитра тонов акцента ограничена и на больших наборах повторяется. Импортированные объекты и старый ввод v1 автоматически не переоформляются. Из-за подтверждённого ограничения текущего нативного экспортёра явный `dataLabels.position` для area/doughnut отклоняется с `chart-label-position`; автоматическое размещение doughnut поддержано. [Исправления и повторная проверка](validation/GENERATION-READABILITY-2026-11-19.md).

## Визуальная регрессия PowerPoint

Для локального PPTX с произвольным количеством слайдов доступен opt-in тест `test/pptx-template-golden.test.mjs`. Требуются Windows, установленный PowerPoint, `pwsh` и Python с Pillow, numpy, scikit-image. Задайте `DSH_PPT_GOLDEN_SOURCE` путём к исходнику и запустите `node --test test/pptx-template-golden.test.mjs`. Необязательные `DSH_PPT_GOLDEN_OUT` и `DSH_PPT_GOLDEN_PYTHON` задают каталог результатов и Python. Для разных исходников используйте отдельные каталоги результатов.

Тест проходит штатный путь PPTX → ZIP шаблона → новый PPTX, возвращает исходный текст в доступные области и первое растровое изображение в поддерживаемую область. Вложенные группы обходятся с пересчётом координат. Непоместившиеся тексты, дополнительные изображения, таблицы и диаграммы фиксируются как потери, а не копируются в обход генератора. Оба файла рендерятся нативным PowerPoint в отдельных сеансах, без подгонки изображений; проверяется SSIM ≥ 0,999 для целых слайдов и видимых областей текста, изображений, таблиц и диаграмм. Также сравниваются эффективные свойства текста через PowerPoint. Нумерация остаётся исключённой согласно политике импорта.

Даже при несовпадении тест сохраняет `report.md`, `metrics.json`, `import-report.json`, `native-differences.json`, `inputs.json` с хешами файлов, PNG сравнений и сгенерированный PPTX. Несопоставленный контент или отличия нативных свойств означают FAIL независимо от общего SSIM. Приватный исходник остаётся локальным и не добавляется в репозиторий; без переменной источника тест пропускается.

## Синтетическая регрессия в CI

Публичные фикстуры `test/fixtures/pptx/` создаются независимо от экспортёра плагина. Обычный `npm test` проверяет импорт 12 текстовых блоков, вложенных групп, смешанного текста, лимит изображений, порядок оформления, диаграмму, объединённые ячейки и OLE-превью. Ожидаемые текущие потери зафиксированы явно.

Обязательная задача CI отдельно выполняет `npm run test:pptx-render` на Linux и Windows: исходник и результат проходят рендеринг через закреплённый WASM 0.2.3 с включёнными свободными шрифтами. Сравнение с проверенными эталонами использует SSIM ≥ 0,999 для полных изображений и областей результата. Отсутствие движка или шрифтов завершает задачу ошибкой.

Отчёт различает `regressionPassed` (результат соответствует проверенному эталону) и `fidelityPassed` (исходник восстановлен с заданной точностью без известных потерь). Зелёная регрессия не скрывает ограничений импорта и не заменяет нативную проверку PowerPoint. Установка тестового runtime, просмотр артефактов и явное обновление эталонов описаны в [инструкции фикстур](../test/fixtures/pptx/README.md).


Для нового сквозного пути с нативным PowerPoint: `node scripts/golden-pptx-scene-native.mjs SOURCE.pptx OUTPUT_DIRECTORY`. Он выполняет импорт → ZIP v3 → чтение ZIP → адресное заполнение исходным содержимым → генерацию проекта/PPTX → нативный рендеринг и сравнение. Каталог вывода должен отличаться от каталога источника. Частные материалы и картинки остаются локально; метрики и ограничения не заменяют проверку новых текстов и данных.


## Рабочий отчёт: заголовки, KPI и сравнения

Встроенный `builtin:working-report` — шаблон 3 с независимыми областями `heading` (обязательный заголовок), `body` (обязательное содержание), `source` (необязательный источник/примечание). Три варианта: широкий контент, заголовок слева, заголовок на акцентной полосе. Формат этого нового шаблона задан явно как 16:9; размеры импортированных PPTX по-прежнему сохраняются без пересчёта.

Типографика задаётся существующим `style.textStyles`: `title` для чисел KPI, `subtitle` для названий альтернатив, `body` для подписей показателей/значений, `caption` для критериев/примечаний. Эти стили применяются к новым представлениям в body; оформление heading редактируется в самом макете. В редакторе шаблона раздел «Типографика» позволяет изменить семейство, размер, цвет и жирность каждой роли, сбросить роль и сохранить личную/разрешённую общую копию. HTML-предпросмотр областей не заменяет проверку сгенерированного KPI/сравнения: их нужно проверить в созданной презентации.

`visual.slotId` должен указывать body, а values заполнять heading отдельно. Содержание, источник, фактические данные, единицы и неизвестные значения задаёт пользователь; стили не создают выводов или дельт. Числа и подписи KPI — разные нативные тексты; критерии сравнения выводятся общими строками один раз. Старые шаблоны без соответствующих ролевых стилей сохраняют прежний вид. Большие/длинные данные могут потребовать другого варианта или явного разделения на слайды: автоматического уменьшения шрифта нет.

Локальная проверка: `node scripts/probe-working-report.mjs OUTPUT_DIRECTORY`. Она создаёт шесть страниц на открытых вымышленных данных, ZIP шаблона и машинный отчёт. Это тест пути генератора, не ответ живой модели.


Отчёт scene-импорта показывает реальные группы/варианты и размещения объектов; число изображений не равно числу уникальных файлов. Признак PPTX saveSubsetFonts сам по себе не доказывает наличие встроенных шрифтов. Невидимые объекты с нулевой площадью перечисляются с причиной пропуска. Предпросмотр schema 3 использует сами макеты, подставляет выбранный короткий/длинный образец и выводит диагностику на языке интерфейса со слайдом/объектом. Предупреждения по образцу не означают автоматически дефект исходной презентации; реальный шрифт и итоговое размещение требуют просмотра. [Исправление предпросмотра и проверки](validation/PPTX-IMPORT-EDITOR-2026-11-19.md).
