# Библиотека шаблонов dsh-ppt

Шаблон = **стиль** (тема, палитра, шрифты, логотип, футер, фоны страниц) +
**каркас страниц** (плейсхолдеры «Заполнить: …») + необязательные
**слайды-образцы**. Дека, созданная из шаблона, остаётся обычным
редактируемым проектом dsh-ppt; незаполненные места дают `template-unfilled`
и статус черновика в `ppt_check`.

## Скоупы и права

| Ключ | Где лежит | Кто видит | Кто управляет |
|---|---|---|---|
| `builtin:<id>` | пакет плагина (`assets/templates/`) | все | никого (read-only) |
| `public:<id>` | `$DSH_HOME/plugins/dsh-ppt/templates/public/` | все | админ |
| `user:<id>` | `$DSH_HOME/plugins/dsh-ppt/templates/users/<логин>/` | только владелец | владелец |

**Админ** (модель плагина auto-memory): авторитетный ответ `webAuth` хоста
(флаг `admin` в cookie-идентичности для панели, `isAdmin` для инструментов);
если хост недоступен — запасной список `admins` в конфиге плагина
(сравнение trim, регистрозависимое). Сессия без owner (локальная/CLI) —
админ; делегированная сессия (fork/fleet) — никогда не админ; всё
сомнительное — не админ (fail-closed). Публикация личного шаблона в общие и
импорт в общие — только админ (`owner` — чей шаблон публикуется).

## Формат bundle

`dsh-ppt-template v1` = ZIP:

```
template.json    # манифест (schemaVersion 1, ≤ 1 MiB)
assets/*         # PNG/JPEG: логотип, фоны (≤ 5 MiB каждый, ≤ 8 MiB суммарно)
README.txt
```

Принимается и голый `template.json`. Защита: whitelist имён файлов, mime
png/jpeg, лимит распаковки 16 MiB, без `..`/симлинк.

## Инструменты

### Создание презентации из шаблона

```
ppt_create { title, templateId: "builtin:corporate-report", lang: "ru" }
```

`templateSamples: false` — без слайдов-образцов. Сценарные `template`
(weekly/defense/project/pitch) работают как раньше.

### Шаблон из примера PPTX / из проекта

```
ppt_template { operation: "create-from-pptx", pptxPath, newTemplateId, name }
ppt_template { operation: "create-from-project", deckPath, newTemplateId, name }
```

Из PPTX извлекается стиль (палитра темы, шрифты, фоны мастеров/макетов,
логотип-эвристика по маленьким картинкам мастера) и каркас заголовков.
Геометрия слайдов не копируется — новые деки рендерит движок dsh-ppt.
В отчёте (`report`) перечислено, что извлечено и предупреждения (нет логотипа,
нестандартный шрифт).

### Импорт / экспорт

```
ppt_template { operation: "import", path | data, scope: "user" | "public" }
ppt_template { operation: "export", templateId, outputDir }
```

`scope: "public"` — только админ. Панель: «Презентации» → переключатель
«Шаблоны» → «Импорт шаблона» (файл до 9 MiB), кнопка «Экспорт» на карточке
(скачивание ZIP).

### Панель: шаблоны внутри «Презентаций»

Отдельного пункта «Шаблоны» в сайдбаре нет. На экране списка проектов
(«Презентации») есть переключатель **Проекты | Шаблоны**; внутри открытого
проекта по-прежнему работает «Редизайн шаблоном» (меняется только оформление,
тексты и порядок страниц не трогаются).

Вкладка «Шаблоны»: карточки (встроенные / общие / личные), «Новый шаблон»,
«Импорт шаблона», «Шаблон из проекта», на карточке — «Создать дек», «Править»
(«Открыть» для чтения), «Дублировать», «Экспорт»; админу ещё «Опубликовать»,
«Сбросить к встроенному» и удаление общих.

Редактор шаблона (разделы «Основное / Стиль / Каркас / Образцы»):

- основное: id (только при создании), название, описание;
- стиль: базовая тема, основной цвет / фон / цвет текста (пусто — цвет темы),
  шрифт, название бренда, футер, логотип, фоны для обложки / раздела /
  контента / финала с режимом вписывания;
- каркас и образцы: страницы шаблона (тип, надзаголовок, заголовок,
  подзаголовок, пункты, заметки), порядок, дублирование, удаление; образцов до 5;
- живое превью справа: мини-дек из пяти страниц (обложка, раздел, список,
  тезис, финал) в стиле черновика, обновляется при каждой правке и ничего не
  сохраняет (`template-preview`, HTML-движок без сборки PPTX).

Права и перекрытие встроенных:

- личный шаблон правит его автор;
- общий и встроенный правит только админ; обычному пользователю шаблон
  открывается для чтения, «Сохранить как копию…» кладёт правки в личные;
- админ, сохранивший встроенный шаблон, создаёт **общую копию с тем же id**
  (ревизия продолжается: встроенная + 1). Она перекрывает встроенный для всех
  пользователей: в списке показывается только копия (метка «заменяет
  встроенный»), ключ `builtin:<id>` в apply / restyle ведёт на неё.
  «Сбросить к встроенному» удаляет копию и возвращает оригинал;
- сохранение защищено от гонок: если шаблон изменили после открытия
  редактора, сервер отклонит запись (`expectedRevision`).

Операции панели (`POST /api/dsh-ppt/workbench`): `template-list` (+ список тем),
`template-get` (+ права и данные картинок), `template-save` (манифест + только
новые файлы `uploads`, неизменённые берутся из `baseKey`), `template-preview`,
`template-duplicate`, `template-create-from-project` (проект по id каталога,
путь из браузера не принимается), `template-import`, `template-apply`,
`template-publish`, `template-delete`.

### Редизайн существующего проекта

```
ppt_template { operation: "apply-to-project", deckPath, templateId | bundlePath,
               expectedRevision, saveAs }
```

Меняется только оформление (theme, brand, фоны по типам страниц
cover/section/content/closing); текст и порядок страниц не трогаются.
По умолчанию правка in-place и попадает в историю undo; `saveAs: true` —
отдельная копия. В манифест проекта пишется происхождение
`template: {id, revision}`, видимое в `ppt_check`.

Панель: кнопка «Редизайн шаблоном» в инспекторе открытого проекта.

### Прочее

```
ppt_template { operation: "list" | "get" | "save" | "delete" | "publish" }
```

## CLI (автономный skill)

```
node build-deck.mjs --title "Отчёт" --template-file corp.zip            # создать из шаблона
node build-deck.mjs --restyle deck.json --template-file corp.zip        # редизайн
node build-deck.mjs --create-template-from-pptx example.pptx \
  --template-id corp --template-name "Corp" --save-template .           # pptx → шаблон
node build-deck.mjs --create-template-from-deck deck.json \
  --template-id corp --template-name "Corp" --save-template .           # проект → шаблон
node build-deck.mjs --export-template public:corp --to ./out            # выгрузка (DSH-библиотека)
```

`--template-key <scope:id>` вместо `--template-file` берёт шаблон из
библиотеки DSH (`DSH_HOME`, для личных — `DSH_USER`).

## Макеты с картинками (schemaVersion 2)

Шаблон может хранить набор **макетов** `style.layouts[]`: у каждого свой фон и список картинок с положением и размером. Координаты `x`, `y`, `w`, `h` — проценты слайда (0–100; левый верхний угол и размер), поэтому не зависят от формата исходного слайда.

```json
{ "id": "cover-1", "name": "Титульный слайд", "layoutType": "cover",
  "background": { "image": "img-ab12cd34.jpg", "fit": "cover" },
  "backgroundColor": "#FFFFFF",
  "images": [ { "image": "logo.png", "svg": "logo.svg", "x": 4, "y": 6, "w": 18, "h": 9,
                "z": 0, "fit": "contain", "role": "logo" } ] }
```

- `layoutType` — `cover | section | content | closing`; `role` — `logo | header | decor | background | photo`; `fit` картинки — `contain | cover | fill`. До 120 вариантов макетов, до 12 картинок на макет.
- Слайд каркаса выбирает макет полем `layoutId`; без него берётся первый макет нужного типа страницы. Шаблоны без `layouts` (schemaVersion 1) работают как раньше: фоны по типам и логотип.
- Картинки лежат под текстом, порядок — по `z`. **HTML-плеер** показывает SVG (если есть), **экспорт PPTX** кладёт PNG/JPEG в те же позиции (фон макета — на весь слайд, ниже текста).
- SVG — только безопасный: без скриптов, `foreignObject`, внешних ссылок и DTD, до 300 КиБ. Иначе импорт оставляет PNG и пишет предупреждение.
- Проект с макетами при «Шаблон из проекта» переносит их вместе с файлами.

### Импорт из PPTX с диска

Панель: «Презентации» → «Шаблоны» → «Шаблон из PPTX». Файл до 64 MiB уходит на сервер сырым телом (`POST api/dsh-ppt/template-upload`, параметры `templateId`, `name`, `scope`, `lang`).

- Анализируются только существующие слайды и используемые ими мастера/макеты. Неиспользуемые внутренние макеты не импортируются.
- Общее оформление объединяется полем `familyId`; структура контента и типографика определяют варианты. Одинаковые варианты переиспользуются через `layoutId`. Мелкие различия положения декора (до округления координат к целому проценту) допускаются внутри одной группы, при этом точная геометрия каждого варианта сохраняется.
- Сохраняются фоны, логотипы, группы картинок, поддерживаемый декор и SVG-пары. Картинка слайда считается логотипом по имени (`logo`, «логотип», «эмблема») либо небольшой рамке у верхнего/нижнего края; остальные картинки слайда заменяются областями `image`. Это эвристика: результат следует просмотреть в редакторе.
- Заголовки, текст и содержательные изображения заменяются областями нового контента `textZones` (`title`, `body`, `image`). Сохраняются разные колонки и их положение. До 6 областей в варианте; превышение отражается в отчёте. Если контентная страница содержит только заголовок, добавляется область текста ниже шапки. Редактор позволяет менять каждую область отдельно.
- Каждая область хранит собственные `textStyle` и `textFrame`: эффективный размер/начертание, шрифт, выравнивание абзаца, вертикальную привязку, внутренние отступы в EMU, интервалы и унаследованный автоподбор. `colorSpec` хранит базовый RGB и преобразования цвета для точного вывода PowerPoint; `fontHints`, `scriptFonts`, `sourceTypeface` и `style.themeFonts` сохраняют параметры подстановки и исходные записи шрифтовой схемы, включая значимые для PowerPoint пробелы в имени. Стиль области имеет приоритет над общими стилями ролей. Редактор, ZIP и повторный экспорт сохраняют эти поля.
- `style.pageSize: { width, height }` хранит точные размеры в EMU. Они сохраняются в ZIP, редакторе, проекте, HTML-предпросмотре, печати и PPTX. A4, портретные и произвольные размеры не адаптируются к 16:9. Старые шаблоны без этого поля используют прежний формат 16:9.
- Отчёт содержит число групп оформления и вариантов, исходные размеры, статистику картинок и список `skippedObjects`: имя/тип, источник (слайд, макет или образец), затронутые слайды и причину. Повторы объектов общего мастера объединяются. Старое поле `skippedShapes` сохраняется для совместимости.
- Неподдерживаемые фигуры и статический текст оформления, требующий ручного переноса, перечисляются в отчёте. Автоматические поля номера, даты и колонтитула не переносятся. Содержимое исходных заголовков и текста не попадает в каркас.
- Крупные растры (> 700 КиБ или > 2560 px) сжимаются на сервере (`jpeg-js`, `pngjs`). Одинаковые изображения хранятся один раз.

## Фоны страниц

Фоны из шаблона применяются по типу страницы: в HTML — CSS-слой
(`data-bgt`), в PPTX — `setSlideBackgroundImage`. Дека без фонов полностью
работоспособна; неподдерживаемый формат собирается без фона с предупреждением.
Движковые ограничения: `style.backgrounds` задаётся только через шаблон.

## Ограничения v1

- Точная геометрия слайдов из PPTX не воспроизводится (только стиль+каркас);
- Пересборка структуры существующего дека по каркасу шаблона (restructure) —
  вне v1;
- Импорт шаблонов по URL и облачный каталог отсутствуют — только файлы;
- Синхронизация библиотеки между машинами — вручную экспортом bundle.

## Визуальная регрессия PowerPoint

Для локального PPTX с произвольным количеством слайдов доступен opt-in тест `test/pptx-template-golden.test.mjs`. Требуются Windows, установленный PowerPoint, `pwsh` и Python с Pillow, numpy, scikit-image. Задайте `DSH_PPT_GOLDEN_SOURCE` путём к исходнику и запустите `node --test test/pptx-template-golden.test.mjs`. Необязательные `DSH_PPT_GOLDEN_OUT` и `DSH_PPT_GOLDEN_PYTHON` задают каталог результатов и Python. Для разных исходников используйте отдельные каталоги результатов.

Тест проходит штатный путь PPTX → ZIP шаблона → новый PPTX, возвращает исходный текст в доступные области и первое растровое изображение в поддерживаемую область. Вложенные группы обходятся с пересчётом координат. Непоместившиеся тексты, дополнительные изображения, таблицы и диаграммы фиксируются как потери, а не копируются в обход генератора. Оба файла рендерятся нативным PowerPoint в отдельных сеансах, без подгонки изображений; проверяется SSIM ≥ 0,999 для целых слайдов и видимых областей текста, изображений, таблиц и диаграмм. Также сравниваются эффективные свойства текста через PowerPoint. Нумерация остаётся исключённой согласно политике импорта.

Даже при несовпадении тест сохраняет `report.md`, `metrics.json`, `import-report.json`, `native-differences.json`, `inputs.json` с хешами файлов, PNG сравнений и сгенерированный PPTX. Несопоставленный контент или отличия нативных свойств означают FAIL независимо от общего SSIM. Приватный исходник остаётся локальным и не добавляется в репозиторий; без переменной источника тест пропускается.
