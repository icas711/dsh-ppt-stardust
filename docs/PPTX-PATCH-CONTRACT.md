# Планируемый контракт патча пользовательского PPTX

Дата: 2026-11-19. Решения согласованы с пользователем; реализация ещё не начата. Документ задаёт границы для согласования следующего этапа, а не описывает доступную команду.

## Назначение и приоритет

Ценность продукта — генератор презентаций и редактор переиспользуемых шаблонов. Патч — дополнительный явный режим редактирования существующего пользовательского файла, сохраняющий его оформление. Он не заменяет генерацию, не является условием запуска пакета 6C и не включается автоматически вместо неудачного импорта.

| Путь | Что происходит с OLE |
|---|---|
| Создание шаблона из PPTX | Только проверенные превью и ограниченные метаданные; бинарники не становятся ассетами и не попадают в ZIP шаблона |
| Генерация нового PPTX из шаблона/сцены | Исходные OLE-бинарники не переносятся |
| Патч исходного пользовательского PPTX | Разрешённые исходные OLE-части остаются непрозрачными внутри соответствующего PPTX; содержимое и связи не изменяются |

Побайтовая сохранность означает SHA-256 распакованных байтов каждой части, а не равенство всего перепакованного ZIP. OLE не исполняется, не активируется, не интерпретируется и не извлекается в отдельные файлы. Его байты не передаются модели, в библиотеку шаблонов или в общий каталог ассетов. Проверка структуры внешнего OPC-пакета и хеширование частей не считаются интерпретацией OLE-контейнера. Содержимое непрозрачного OLE не сканируется и не объявляется безопасным.

Сохранение результата под новым именем оставляет вложения внутри выходного PPTX этого же пользователя; оно не разрешает экспорт отдельных вложений или включение исходного архива в переиспользуемый шаблон. Проект хранит ссылку на пользовательский источник, SHA-256, карту адресов и историю операций. Скрытого копирования исходника с вложениями в библиотеку/общее хранилище нет.

## Первая операция и сохранение

- Первая версия меняет только текст существующего `a:r/a:t` на слайде. Адрес: канонический `slidePart`, `shapeId`, индексы абзаца/фрагмента, ожидаемый старый текст либо его хеш; дополнительно проверяется хеш всего исходника.
- Форматирование `rPr`/`pPr`, границы и группы, темы, диаграммы, OLE, relationships и остальные части сохраняются. Новые абзацы, смена типа/структуры, правка данных диаграмм и OLE не входят в эту операцию.
- Неоднозначный адрес, смена ревизии или недопустимая операция — ошибка до записи, без поиска по похожему тексту и без неявного перехода в генератор.
- Исходник не перезаписывается по умолчанию. Результат сохраняется атомарно по выбранному пути; операции имеют undo и контроль ревизии. Повторно прочитанный источник проверяется до записи, чтобы исключить изменение после предварительной проверки.
- Allowlist изменений результата для текстового патча: только адресованные `ppt/slides/slideN.xml`. Их структурный XML-diff допускает только согласованные значения `a:t`; порядок объектов, атрибуты и остальное содержимое неизменны. Пересериализация `[Content_Types].xml` допустима только при доказанном равенстве полного набора Default/Override и отсутствии неоднозначных объявлений. Другие части, в том числе `.rels`, сохраняются побайтово.
- `setChartSpec` не используется для точного патча чужого графика: диагностикой подтверждены перестроение оформления и неверная ссылка `externalData`. Будущий патч cache/XLSX требует отдельного контракта и приёмки.

## Разрешительный список входного пакета v1

Это явный начальный список для будущей реализации. Неизвестная часть, content type или relationship отклоняет весь патч с конкретной причиной; исходник остаётся нетронутым. Разрешение применяется к сочетанию **канонический путь + точный content type + разрешённые входящие связи**, а не только к расширению или имени каталога.

В таблице `*` — ровно одно имя файла без разделителей пути, `N` — положительный десятичный номер. Псевдонимы типов раскрываются в точные строки:

- `PML:` = `application/vnd.openxmlformats-officedocument.presentationml.`
- `DML:` = `application/vnd.openxmlformats-officedocument.drawingml.`
- `OFFICE:` = `application/vnd.openxmlformats-officedocument.`

| Части | Допустимый content type | Поведение текстового патча |
|---|---|---|
| `[Content_Types].xml` | Служебный файл OPC, проверенные Default/Override | Только семантически эквивалентная сериализация |
| `_rels/.rels` и соответствующие разрешённым частям `_rels/*.rels` | `application/vnd.openxmlformats-package.relationships+xml` | Все связи проверяются; байты сохраняются |
| `ppt/presentation.xml` | `PML:presentation.main+xml` | Сохранять |
| `ppt/slides/slideN.xml` | `PML:slide+xml` | Только адресованные значения текста |
| `ppt/slideLayouts/slideLayoutN.xml`, `ppt/slideMasters/slideMasterN.xml` | Соответственно `PML:slideLayout+xml`, `PML:slideMaster+xml` | Сохранять |
| `ppt/notesSlides/notesSlideN.xml`, `ppt/notesMasters/notesMasterN.xml` | Соответственно `PML:notesSlide+xml`, `PML:notesMaster+xml` | Сохранять |
| `ppt/theme/themeN.xml`, `ppt/theme/themeOverrideN.xml` | Соответственно `OFFICE:theme+xml`, `OFFICE:themeOverride+xml` | Сохранять |
| `ppt/charts/chartN.xml` | `DML:chart+xml` | Сохранять |
| `ppt/charts/styleN.xml`, `ppt/charts/colorsN.xml` | Соответственно `application/vnd.ms-office.chartstyle+xml`, `application/vnd.ms-office.chartcolorstyle+xml` | Сохранять |
| `ppt/presProps.xml`, `ppt/viewProps.xml`, `ppt/tableStyles.xml` | Соответственно `PML:presProps+xml`, `PML:viewProps+xml`, `PML:tableStyles+xml` | Сохранять |
| `ppt/commentAuthors.xml`, `ppt/comments/commentN.xml` | Соответственно `PML:commentAuthors+xml`, `PML:comments+xml` | Сохранять |
| `docProps/core.xml`, `docProps/app.xml` | Соответственно `application/vnd.openxmlformats-package.core-properties+xml`, `OFFICE:extended-properties+xml` | Сохранять |
| `ppt/media/*.png`, `*.jpg`, `*.jpeg` | Соответственно `image/png`, `image/jpeg` | Сохранять исходные части |
| `ppt/media/*.svg`, `*.emf`, `*.wmf` | Соответственно `image/svg+xml`, `image/x-emf`, `image/x-wmf` | Только непрозрачное сохранение, не обещание поддержки импортом/превью |
| `ppt/drawings/*.vml` | `OFFICE:vmlDrawing` | Непрозрачное сохранение после проверки связей; не исполнять и не преобразовывать |
| `ppt/embeddings/*.bin` | `OFFICE:oleObject` | Только исходная внутренняя связь `oleObject`, неизменные байты |
| `ppt/embeddings/*.xlsx` | `OFFICE:spreadsheetml.sheet` | Только внутренняя связь `package` от разрешённой диаграммы; исходные байты сохраняются |

`application/xml` в Default по расширению не разрешает произвольные XML-части: для структурированных частей обязательны соответствующий Override и ожидаемый корневой namespace. OLE и VML ссылаются только на разрешённые части; наличие разрешённого каталога не разрешает неизвестный файл в нём. Неизвестные шрифтовые, мультимедийные, customXml и другие части требуют отдельного расширения списка с фикстурой, а не автоматического допуска.

### Точные типы и направления relationships

Префиксы ниже — сокращение документации, не разрешение по началу строки. Реализация сравнивает полные URI, собранные из префикса и **одного явно перечисленного** имени:

- `OD:` = `http://schemas.openxmlformats.org/officeDocument/2006/relationships/`
- `PKG:` = `http://schemas.openxmlformats.org/package/2006/relationships/`
- `MS11:` = `http://schemas.microsoft.com/office/2011/relationships/`

| Тип | Разрешённый источник → цель |
|---|---|
| `OD:officeDocument` | Корень → `ppt/presentation.xml` |
| `PKG:metadata/core-properties`, `OD:extended-properties` | Корень → соответствующий `docProps` |
| `OD:slide` | Презентация → слайд; слайд → существующий слайд для внутреннего перехода; notesSlide → свой слайд |
| `OD:slideMaster`, `OD:slideLayout` | Презентация/макет → мастер; мастер/слайд → макет |
| `OD:notesMaster`, `OD:notesSlide` | Презентация/заметки → мастер заметок; слайд → свои заметки |
| `OD:theme`, `OD:themeOverride` | Презентация/мастер/мастер заметок/макет/диаграмма → соответствующая тема |
| `OD:presProps`, `OD:viewProps`, `OD:tableStyles`, `OD:commentAuthors` | Презентация → соответствующая служебная часть |
| `OD:comments` | Слайд → комментарии |
| `OD:image` | Слайд/макет/мастер/заметки/мастер заметок/диаграмма/VML → разрешённая часть `ppt/media` |
| `OD:chart` | Слайд → `ppt/charts/chartN.xml` |
| `MS11:chartStyle`, `MS11:chartColorStyle` | Диаграмма → соответствующие style/colors |
| `OD:oleObject` | Слайд → исходная разрешённая OLE `.bin` |
| `OD:package` | Диаграмма → разрешённая `.xlsx`; не произвольный вложенный пакет |
| `OD:vmlDrawing` | Слайд/заметки → разрешённый VML |
| `OD:hyperlink` | Слайд/макет/мастер/заметки → обычная внешняя гиперссылка по правилу ниже |

Все связи, кроме разрешённого `OD:hyperlink`, имеют внутреннюю цель, существующую в этом же пакете. Проверяются даже неиспользуемые relationship-записи; не допускаются неоднозначные Id, path traversal, абсолютные файловые/UNC-пути и неканонические обходы ограничений. Варианты Strict OOXML и дополнительные URI не приравниваются к перечисленным автоматически.

### Обычные гиперссылки и запреты

Согласованное исключение для внешних relationships — `OD:hyperlink` с `TargetMode="External"` и обычным URI `http`, `https` или `mailto`. Ссылка сохраняется без изменения, не открывается, не загружается и не служит источником данных. Внутренние переходы между слайдами проверяются как внутренние `OD:slide`.

`file:`, UNC, `javascript:`, `data:`, неизвестные схемы, внешние изображения/книги, связанные OLE и остальные внешние relationships отклоняются. ActiveX, макросы и неизвестные типы также не попадают в allowlist. `vbaProject` отклоняется по имени части, content type и relationship, включая обнаруженные объявления без ожидаемого имени; переименование файла не является обходом.

Встроенная известная XLSX проверяется как ограниченный OPC ZIP без выполнения формул или содержимого: немакросная книга, отсутствие VBA/ActiveX/неизвестных частей и внешних ресурсов, только разрешённые обычные гиперссылки. Одного расширения `.xlsx` недостаточно. Произвольный OLE `.bin` для такой проверки не раскрывается: гарантия отсутствия макросов относится к проверяемым OPC-пакетам, а не к содержимому непрозрачного вложения.

### Allowlist вложенной XLSX v1

Префикс `SML:` = `application/vnd.openxmlformats-officedocument.spreadsheetml.`; остальные сокращения определены выше. Книга сохраняется побайтово целиком, включая проверенные связи. Чтение структуры для допуска не разрешает извлекать её данные в шаблон или менять книгу в текстовой операции.

| Части | Точный тип | Разрешённые связи |
|---|---|---|
| `[Content_Types].xml`, `_rels/.rels`, соответствующие частям `_rels/*.rels` | Служебный OPC и `application/vnd.openxmlformats-package.relationships+xml` | Только перечисленные для этой книги |
| `xl/workbook.xml` | `SML:sheet.main+xml` | Корень → книга через `OD:officeDocument` |
| `xl/worksheets/sheetN.xml` | `SML:worksheet+xml` | Книга → лист через `OD:worksheet` |
| `xl/styles.xml`, `xl/sharedStrings.xml` | Соответственно `SML:styles+xml`, `SML:sharedStrings+xml` | Книга → соответствующая часть через `OD:styles`, `OD:sharedStrings` |
| `xl/theme/themeN.xml` | `OFFICE:theme+xml` | Книга → тема через `OD:theme` |
| `xl/tables/tableN.xml` | `SML:table+xml` | Лист → таблица через `OD:table` |
| `xl/printerSettings/printerSettingsN.bin` | `SML:printerSettings` | Лист → настройки через `OD:printerSettings`; только непрозрачное сохранение |
| `docProps/core.xml`, `docProps/app.xml` | Те же точные типы, что во внешнем пакете | Корень → соответствующие метаданные через `PKG:metadata/core-properties`, `OD:extended-properties` |
| Внешняя обычная гиперссылка | Не является ZIP-частью | Лист → URI через `OD:hyperlink`, только по правилу http/https/mailto |

Список охватывает классы частей четырёх книг рабочего примера, включая настройки печати в двух из них; содержимое книг не публикуется. Не допускаются рекурсивные вложения, externalLinks, query/connections и другие не перечисленные части/связи. Превышение бюджета или неизвестная часть отклоняет весь патч, а не удаляет её из книги.

Предварительная проверка ограничивает сжатый исходник 64 МиБ, суммарные распакованные данные внешнего пакета и проверяемых XLSX — 64 МиБ, суммарное число записей — 20 000; вложенность ограничена внешним PPTX и непосредственно связанными книгами. Пределы входят в версионированную общую политику и проверяются до передачи в SDK; ZIP-имена, повторяющиеся записи и relationships проверяются однозначно. Расширение списка/бюджетов требует отдельного изменения контракта и фикстур.

## Отчёт и критерии приёмки

- До записи: режим `patch`, версия политики, хеш источника, операции и их адреса, наличие исходных вложений. Для каждого OLE — part, связанные слайды/объекты, размер, SHA-256 и статус «непрозрачное, не интерпретировалось»; байты и догадки о содержимом в отчёт не попадают.
- После записи: хеш результата, изменённые части и узлы, SHA-256 до/после для каждого OLE и остальных сохраняемых частей, подтверждение неизменных relationships. OLE со статусом «без изменений» только при фактическом совпадении хеша. При несовпадении результата нет: временный файл не публикуется.
- Отклонение содержит код, part/relationship и причину, без тихого удаления или очистки файла. Допустимые диагностические коды планируются в общем контракте, не задаются отдельно в клиенте.
- Независимые синтетические фикстуры: исходный OLE и его совместно используемые связи; обычные гиперссылки; VBA под разными именами; внешние картинки/книги и файловые ссылки; неизвестные часть/тип/связь; вложенная XLSX; повреждённые/неоднозначные ZIP и смена хеша источника. Наличие OLE само по себе не причина отказа.
- Структурный gate: разрешены только согласованные текстовые изменения, байты OLE и нетронутых частей неизменны. Нетронутые слайды — SSIM 1,000000 в закреплённом окружении. Для изменённого слайда отдельно проверяются сохранность вне согласованной области и переполнение.
- Рабочий шестислайдовый пример содержит 4 OLE-бинарника, не содержит `vbaProject` и внешних relationships; его допуск проверяется реальным валидатором всей политики, а не только этой инвентаризацией. Приёмка требует успешного текстового патча с сохранением всех четырёх вложений и нетронутых слайдов.
- При переключении в создание шаблона/новой сцены непрозрачные части недоступны пути экспорта ассетов. ZIP шаблона и новый сгенерированный PPTX проверяются на отсутствие OLE независимо от успешного патча.

## Следующий согласуемый объём

Сначала согласовать реализацию: общий версионированный список внешнего и вложенного OPC, предварительную проверку и отчёт, адресный текстовый патч, атомарное сохранение и структурные/визуальные проверки. Изменения диаграмм — отдельный последующий этап. Пакет 6C генератора/редактора шаблонов сохраняет самостоятельный приоритет.
