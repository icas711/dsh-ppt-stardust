# Сквозной тест обычной генерации из содержания

Дата подготовки: 2026-11-21. Минимальная сборка сервера: ru.29. Изменений плагина или нового развёртывания для этого теста нет.

## Что проверяется

Модель получает исходный текст и PNG, сама составляет восемь смысловых слайдов cards/process/timeline/comparison/big_number/chart/table/image, затем один обычный ppt_create создаёт смешанную презентацию на public:dkp. Это следующий шаг после принятия изолированных примеров; готовый slides/spec в комплект не включён. Тест не запускает A/B/C и не выбирает победителя по скорости.

Комплект в smoke/ordinary-content-pilot содержит только:

- material.txt — синтетическое содержание: направления с оговорками, порядок, даты и месяц без дня, варианты с неизвестной стоимостью, показатели 30/0, региональные заявки 17/9/5, реестр из 12 строк и описание иллюстрации.
- source.png — исходная контрольная картинка 800 × 400 с четырьмя углами.
- prepare-request.py — стандартная библиотека Python 3.9+: читает модельный draft.json со slides, встраивает исходные текст/PNG, вычисляет contentHash и байтовую requestSha256. Не составляет слайды, не вызывает модель/плагин и не исправляет факты. Существующий выходной файл не перезаписывает.

Архив оператора ordinary-content-pilot.zip, SHA-256: `b65d286823a8942f5d41f24ecd702a0bf3861ccdcf717ca9a6c613848eef6463`. В архиве нет контрольного draft/spec. Исходники публичные, независимы от частных документов пользователя.

## Выполнение

Роли вложений — содержание; цель — показать руководителю план и результаты подготовки пилота, русский язык, подробность с сохранением оговорок. Согласованный шаблон public:dkp, demo, восемь смысловых слайдов без обложки, дополнительные физические страницы разрешены. Эти параметры входят в пользовательский промпт; повторное согласование не требуется.

Модель записывает draft.json как объект только со slides. Порядок типов: cards, process, timeline, comparison, big_number, chart, table, image. Для всех visual.sourceRefs используется material; image.assetId — pilot-image. Исполняемый подготовщик запускается по прямой инструкции пользователя:

```text
python3 <папка-комплекта>/prepare-request.py <draft.json> --out <новый-request.json>
```

Для данного набора числа показателей/диаграммы — целые; денежные значения остаются строками. Подготовщик отклоняет float, не нормализует строки. Он печатает три поля для вызова ppt_create: title, requestFile, requestSha256. Текст и base64 повторно в аргументы инструмента не набираются. При ошибке тест останавливается без переписывания входа, пересчёта уже выданных сумм и повторных вызовов.

После успеха пользовательский промпт явно запрашивает HTML/PPTX/PDF при наличии, предупреждения и draft.json для проверки извлечения. Внутренний проект и прочие технические файлы не требуются. Визуальную приёмку модель не объявляет. Оператор сообщает время и оценку, передаёт результат текущего чата.

## Проверка и текущий статус

Локально с контрольным draft вне передаваемого комплекта проверены подготовщик, совпадение Python/JS contentHash и вызов requestFile на сохранённом public:dkp. Получены восемь смысловых слайдов, девять физических страниц, включая две страницы реестра. Все девять локальных страниц просмотрены в рендере PowerPoint; видимых обрезаний не обнаружено. Подготовщик также запущен из распакованного ZIP: результат совпал побайтово. Это проверка пригодности набора, а не запуск модели в DSH и не результат сквозного серверного теста.

После серверного запуска отдельно проверяются полнота оговорок, хронология без выдуманного дня, единые критерии, unknown и известный ноль, категории/значения, все 12 строк/порядок/форматирование/U+00A0, исходные байты изображения и компоновка. contentHash подтверждает неизменность подготовленного draft после вычисления; он не доказывает точность извлечения из material.txt. Успех экспорта не заменяет пользовательскую визуальную оценку.
