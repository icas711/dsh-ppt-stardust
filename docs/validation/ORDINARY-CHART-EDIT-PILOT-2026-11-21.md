# Изменение чисел pie и пересчёт подписей

Дата: 2026-11-21. ru.35, компоненты 15. Серверная приёмка ожидается.

## Найденная проблема и контракт

После приёмки изменения заголовка следующий сценарий проверяет собственно числовую правку. Локальное воспроизведение на ru.34 показало: серия меняется со 100/60/40 на 80/60/60, но собственный текст точек остаётся 100/60/40 и 50/30/20%. Это ограничение прежнего статического текста уже было отмечено в протоколе ru.33; оно мешает безопасной обычной правке через плагин.

Новые автоматически оформленные pie ru.35 хранят в scene-chart связь amountLabels={unit,showPercent}. При нормализации/правке серия и категории определяют подписи заново. Исходная единица, неразрывные пробелы и стили подписей сохраняются, проценты по умолчанию отсутствуют. Полная серия заменяется через текущий chart, полученный адресным ppt_check, с сохранением связи и остальных параметров. Модель меняет только values, не переписывает подписи.

Связь допустима только для pie и проверяет непустую единицу до 128 символов и boolean showPercent. Она хранится в проекте, в native Office spec не передаётся. Явные ручные подписи и старые проекты без amountLabels не переосмысляются автоматически. Для перехода к ручным подписям связь можно опустить в полном заменяемом chart. Числа и вложенные книги нативные. При внешнем редактировании PPTX в Office собственный текст подписей сам не пересчитывается; это обновление гарантируется только через плагин.

## Контрольный сценарий

Используется прежний принятый ordinary-pie-amount-pilot.zip и свежий create на ru.35. Первый слайд не изменяется. На втором слайде пользователь явно задаёт новые синтетические значения: Оборудование 80 тыс. ₽, Лицензии 60 тыс. ₽, Обучение 60 тыс. ₽. Единый бюджет остаётся 200 тыс. ₽, проценты включены, ожидаются 40/30/30%.

В одном чате: проверка/личный импорт шаблона, один requestFile-create, один адресный check второго слайда, один edit только values второй диаграммы и один undo. После edit скопировать доступные HTML/PPTX/PDF в edited, после undo в restored. Сохранять полный текущий chart и менять только series[0].values, сохраняя прочие серии/параметры. Использовать deckPath и expectedRevision из фактических ответов. Не пересоздавать проект, не выполнять дополнительные check/render после успешных операций. При ошибке остановиться. Выдать оба состояния, предупреждения и журнал ревизий без внутреннего JSON проекта.

Пользователь смотрит новые суммы и проценты в edited и их возврат в restored. Автоматическая визуальная приёмка не объявляется.

## Локальные проверки

Реальная обычная цепочка create/check/edit/undo прошла ревизии 0/1/2 с одним deckId. В edited второй график содержит 80/60/60 и подписи с единицей и долями 40/30/30%, его рамка сохранена. Первая страница совпала с исходной. После undo весь массив slides совпал с исходным, XML обеих диаграмм и обеих страниц вернулся побайтово.

Регрессионный тест проходит реальные build/edit/undo и проверяет обе опции процентов, пересчёт текста по новым числам, данные нативного кэша и XLSX, неизменность рамок, идемпотентную нормализацию и возврат slides. Дополнительно проверяются ручные подписи и ошибки неверных параметров связи. Результаты пользователя пока не получены.

PowerPoint-рендеры после edit и undo получены; второй слайд обоих состояний просмотрен. Новые суммы и доли читаются, числа и единицы держатся вместе; после undo видны исходные 100/60/40 и 50/30/20%.

Полный npm test: 622 теста, 620 passed, 2 skipped, 0 failures. Первый полный прогон получил EPERM при rename временного каталога в независимом visual-тесте; повторный полный прогон прошёл без изменения кода.
