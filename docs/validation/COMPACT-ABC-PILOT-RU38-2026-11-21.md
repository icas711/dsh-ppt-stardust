# Сравнительный пилот A/B/C на ru.38

Дата подготовки: 21.11.2026. Статус: получены первые три живых результата cards/light ([разбор](COMPACT-ABC-CARDS-RU38-2026-11-21.md)); техническая проверка пройдена, пользователь визуально принял A и отклонил B/C. Продолжение этой версии отложено для исправления карточек в ru.39; ниже сохранён исходный протокол ru.38, а не инструкция развёртывать старую версию. Остальные девять запусков ещё не получены. Основание — этапы 6–7 [плана](../FEATURE-PLAN-COMPACT-GENERATION-2026-11-20.md). Шрифты закрыты серверным архивом 1825 и подтверждением пользователя; повторная проверка в эту серию не входит.

## Цель и условия

Измерить время до принятого результата и причины отказов при одинаковых материалах, шаблоне и модели. A — свободная scene; B — один плановый spec; C — scenario и spec. Общий бюджет — максимум два исправления на задание: до трёх ответов для A/B и четырёх для C.

Закрепить dsh-ppt `0.20.6-ru.38`, модель `glm-5.3-flash`, фактические DSH/provider и доступный fingerprint из report. Каждый запуск — новый чат без переноса памяти и файлов других запусков. Встроенные источники — синтетическое содержание, встроенный шаблон — оформление; роли уже определены. Рубрики/эталонные ответы модели не передавать. Во время серии плагин не обновлять.

Обычные tableSpec/visualSpec уже проверены в отдельных сценариях. Их приёмка и замеры на старых версиях не становятся результатами новой серии A/B/C. Числовой порог ускорения определить после этого пилота, до подтверждающих повторов.

Это четыре диагностические группы, не приёмка всех 48 сочетаний задания/шаблона. Декор контрольного шаблона намеренный; оценивать сохранение оформления и отсутствие наложений, не требовать переработки дизайна. Не запускать сразу полное подтверждающее расписание.

Запуски выполнять последовательно: сначала завершить предыдущий, затем начинать следующий. Первые три опыта пересекались по серверному времени; они сохранены как диагностические результаты с этим ограничением, без вывода о победителе.

## Сообщение для первого нового чата DSH

Выбрать `glm-5.3-flash`, проверить установленную ru.38 и отправить:

```text
Проведи один экспериментальный запуск dsh-ppt A/B/C на установленной версии 0.20.6-ru.38: режим A, задание cards, шаблон light. Используй ppt_generation: сначала operation:list, затем operation:start с experimental:true, mode:"A", caseId:"cards", templateKey:"light". Если фактическая версия отличается, сообщи её и не начинай эксперимент.

Встроенные источники этого задания — содержание, встроенный light — оформление; остальные требования бери из brief. Уточняй через ask_user_question только действительно недостающие сведения, известные ответы не переспрашивай.

Выполняй возвращаемые nextRequest через operation:submit с точными runId и expectedTurn до завершения. responseText должен содержать JSON для текущего nextRequest. Не вызывай ppt_create, не запускай другие задания, не начинай заново после ошибки и не обходи лимит исправлений. При неопределённом результате вызова сначала получи operation:status.

В конце получи operation:report и выдай ссылки на отчёт и все полученные HTML/PPTX/PDF, а также статус и предупреждения. При ошибке тоже сохрани report. Не объявляй визуальную приёмку или победителя. Не выполняй дополнительные check/render для этого замера.
```

Следующие запуски — тот же текст с заменой режима/caseId/templateKey по таблице, каждый в новом чате. Номер серии и чата записывает оператор. После каждой тройки сохранить результаты и выполнить просмотр; не скрывать неуспешный опыт дополнительным незапланированным повтором.

## Что сохранить для разбора

Для каждого запуска сохранить исходный запрос, историю DSH с tool calls, report, все полученные файлы и показанные интерфейсом показатели времени/usage. Записать фактические версии, провайдера/модель, номер чата/runId, известное состояние кеша (иначе unknown), ручные вмешательства и итог даже при ошибке.

Использовать форму ниже отдельно для каждого номера; она относится к UI-протоколу, не является входом локального review-compact:

```json
{
  "series": "compact-abc-ru38-2026-11-21",
  "number": "01",
  "caseId": "cards",
  "templateKey": "light",
  "mode": "A",
  "chatId": null,
  "runId": null,
  "versions": {"installedPlugin": null, "dsh": null, "provider": null, "model": null},
  "cacheCondition": "unknown",
  "timing": {"startedAt": null, "firstResponseAt": null, "finishedAt": null, "acceptedAt": null, "clarificationMs": null, "reviewMs": null},
  "dshMetrics": {"elapsedSeconds": null, "ttftSeconds": null, "tokensPerSecond": null},
  "providerUsage": {"inputTokens": null, "outputTokens": null, "cost": null, "currency": null, "evidence": null},
  "outcome": null,
  "reportPath": null,
  "transcriptPath": null,
  "artifactPaths": [],
  "checks": {"facts": null, "filesOpen": null, "noCriticalOverlap": null, "readable": null, "templateStyle": null, "editable": null},
  "manualInterventions": [],
  "limitations": []
}
```

Время записывать с часовым поясом. Интерфейсный elapsed, серверные границы протокола и время до человеческой приёмки — разные показатели. TTFT не выводить из firstSubmissionAt. Неизвестные значения оставлять null; токены/стоимость не оценивать по длине ответа или словам модели. Уточнения и время просмотра учитывать отдельно. Состояние кеша не выводить из порядка запусков.

Проверить факты, числа, единицы, порядок и оговорки по исходному материалу; открыть файлы, просмотреть все страницы, проверить обрезку/наложения, читаемость, сохранение шаблона и нативную редактируемость. Человеческую оценку привязать к конкретным файлам и их SHA-256 при разборе. exported не означает accepted; отзыв модели не заменяет просмотр.

## Локальный резервный комплект

Подготовка без вызовов модели:

```powershell
node scripts/generation-evaluation.mjs prepare-compact .test-output/compact-generation-kit-ru38-2026-11-21
node scripts/generation-evaluation.mjs review-compact .test-output/compact-generation-kit-ru38-2026-11-21 .test-output/compact-generation-review-ru38-2026-11-21
```

Комплект закрепляет версии, входы и код хешами; содержит 12 пилотных и 432 возможных подтверждающих строки. Все они первоначально not-run. Код выхода 1 у предварительного review ожидаем при отсутствии принятых попыток. Файловый replay и UI-report имеют разные форматы: UI-экспорты не записывать автоматически как выполненные строки локального комплекта. Локальную повторную сборку не считать живым замером.

## Переход к повторным измерениям

После 12 запусков составить таблицу исходов, времени, числа вызовов/исправлений и дефектов отдельно по каждой группе. Зафиксировать числовой порог ускорения и условия сравнения, выбрать перспективные варианты и выполнить минимум три повтора каждого выбранного сочетания с чередованием порядка. Провалы и незавершённые опыты остаются в отчёте. При преимуществе в пределах разброса признать отсутствие убедительного победителя. До получения этих данных этапы 6–7 остаются открытыми.
