# Приёмка объектной модели — 2026-11-19

Базовые функции проведены через импорт, шаблон, проект, инструменты и интерфейс. Полная визуальная приёмка рабочего PPTX остаётся открытой: ниже зафиксирован FAIL при неизменном пороге SSIM ≥ 0,999. Частные презентации, изображения и текст в репозиторий не включены.

## Реализованные пакеты

- Проекты v2: создание/чтение, правки по ID, копирование, перестановка, удаление, undo, контроль ревизий и явная атомарная миграция всей истории. Привязанные dataModel-проекты сохраняют прежний путь; миграция связей пока отклоняется.
- Полный список поддерживаемых объектов вместо шести зон: текст с фрагментами, изображения, группы, базовые фигуры/линии, таблицы и нативные диаграммы. Исходные размеры страницы сохраняются.
- Шаблоны v3: существующие слайды, семейства/варианты, типизированные слоты и заполнение по ID. Неизвестные области — ошибки; несопоставленный при редизайне контент сохраняется с предупреждением.
- Нативные таблицы с объединениями и несколько диаграмм на слайде. Правки чисел обновляют встроенные Excel-книги. OLE-бинарники не переносятся; разрешены только проверенные растровые превью.
- Явные семантические процессы, карточки сравнения, иерархии, связи и временные шкалы. Списки не получают выдуманных чисел или связей. Преобразование имеет undo и проверяет сохранность пунктов.
- Редактор объектов, загрузка изображений, данные графиков/ячеек, типографика, роль и геометрия; сохранение ввода при конфликте ревизий с объединением независимых изменений. Смысловой ввод для репетиции и адресные ограниченные визуальные действия.

## Проверки

Полный локальный набор после заключительных правок: **411/411**, без пропусков, включая прежние opt-in проверки исходного PPTX и отмену асинхронной загрузки изображения в редакторе.

Обязательный переносимый golden: **16 случаев**, все SSIM 1,000000 по странице и проверяемым областям. Пять случаев проходят настоящий путь PPTX → ZIP v3 → чтение ZIP → заполнение слотов → новый PPTX; остальные проверяют независимую сериализацию и совместимость старых макетов. Сравнение не использует подгонку изображений и заменяемые эталоны для scene-fidelity.

Проверки выполнены локально на Windows. В CI настроены Windows/Ubuntu и закреплённый WASM-рендерер; удалённый CI в этом проходе не запускался. Для legacy-bullets одинаковая подстановка Arial на стороне источника и результата отмечена явно; остальные случаи требуют отсутствия недостающих шрифтов.

Новый сквозной нативный golden двухслайдового источника: **PASS**, оба SSIM 1,000000, отличий нативных свойств текста — 0. Проверены исходные жирность/красный цвет и заголовок справа-вверху.

## Рабочий шестислайдовый источник

| Слайд | SSIM до развития модели | SSIM нового пути | Не сопоставлено объектов |
|---|---:|---:|---:|
| 1 | 0.979616 | 1.000000 | 0 |
| 2 | 0.794821 | 0.824410 | 11 |
| 3 | 0.632885 | 0.752402 | 2 |
| 4 | 0.788351 | 0.872352 | 3 |
| 5 | 0.709305 | 0.861232 | 6 |
| 6 | 0.713756 | 0.939685 | 0 |

Результат: **FAIL**. Нативных отличий текста: **42**. Каждый слайд улучшился относительно исходной проверки из плана, но слайды 2–6 ниже 0,999. Числа диагностических объектов старого и нового импортёров нельзя трактовать как одинаковую инвентаризацию: новая модель учитывает больше типов и оформление.

Остаются нестандартная геометрия, составные фигуры с текстом/заливкой, расширенные списки и некоторые параметры текста, OLE без PNG/JPEG-превью, сложное наследование оформления и несогласованные кеши диаграмм. При несовпадении категорий и значений исходные данные не угадываются. Эти случаи требуют дальнейших исправлений; наличие диагностической записи не означает точного переноса.

## Воспроизведение

- `npm test` — сборка, модульные и интеграционные проверки. Для прежнего нативного golden задайте `DSH_PPT_GOLDEN_SOURCE` и `DSH_PPT_EXAMPLE`.
- `npm run test:pptx-render` — обязательные синтетические рендеры, включая ZIP v3.
- `node scripts/golden-pptx-scene-native.mjs SOURCE.pptx OUTPUT_DIRECTORY` — новый сквозной путь с нативным Microsoft PowerPoint; код выхода ненулевой при FAIL. Вывод хранить отдельно от исходника.

Локальные частные артефакты этого прохода: `.test-output/golden-scene-example/` и `.test-output/golden-scene-example2/` (PPTX, ZIP, сравнения, `overview.png`, подробная диагностика). Они игнорируются Git. Обезличенные машиночитаемые результаты: [scene-acceptance-2026-11-19.json](scene-acceptance-2026-11-19.json).

Последующий [разбор слайдов 2–6](PPTX-FIDELITY-DIAGNOSIS-2026-11-19.md) отделяет потери импорта от fallback-отрисовки и проверяет возможность патча исходного пакета. Он не меняет зафиксированный здесь FAIL.
