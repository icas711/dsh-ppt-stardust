# Два ряда данных: генерация из исходного текста

Дата: 2026-11-21. Сервер ru.36, компоненты 15. Изменения кода и обновление сервера не требуются. Серверный запуск ожидается.

## Цель и вход

После проверки одиночных рядов и короткой числовой правки следующий отдельный сценарий проверяет обычную генерацию двухрядных column/line из нового исходного текста, без готового request.json. Это проверка извлечения чисел, привязки к категориям/месяцам и легенд нескольких рядов, а не новый A/B/C или повтор принятого pie.

ZIP ordinary-multiseries-pilot.zip содержит только template.json и material.txt. Первый файл задаёт оформление, второй содержание. Исходник материала публичный и полностью синтетический: smoke/ordinary-multiseries-pilot/material.txt. Шаблон прежний, smoke/ordinary-chart-kinds-pilot/template.json, user:ordinary-dark-clean-20261121.

- SHA-256 ZIP: `5462dab2c844e70c03bb5a4f8c922065bf7619821ea8d9d6900d7158700b4966`.
- SHA-256 material.txt: `da2433c1ebba51446584fa3131e660f28d3a6f31b1c96c3fd84ff609f40141cb`.
- SHA-256 template.json: `7bc9032dcfdcad5e06840252a18805ab2c7d7107dfc45a5e81ea152409640f3a`.

Ровно два слайда:

1. «План и факт затрат», сгруппированный column, единица тыс. ₽. Категории Подготовка/Разработка/Проверка/Запуск; План 80/120/60/40, Факт 70/100/55/35. Два ряда одной диаграммы, не накопление и не проценты.
2. «Заявки по месяцам», line, единица заявок, ordered=true. Месяцы 2026-09/2026-10/2026-11/2026-12; Север 17/22/19/27, Юг 9/14/12/18. Месяцы упорядочены, это количества двух регионов, не доли целого.

## Локальная проверка

Из материала подготовлен только локальный контрольный visualSpec; в пользовательском комплекте его нет. Реальные личный import и обычный create дали две страницы. В нативном PPTX проверены по два ряда, имена, все категории/месяцы и 16 значений, обе легенды. Оба слайда просмотрены в PowerPoint: подписи, единицы и легенды читаются, линии/группы столбцов различимы; видимых обрезаний и критических наложений нет. Это контроль пригодности сценария, не свидетельство извлечения материала серверной моделью.

Код плагина не менялся. Полный npm test для нового текста и документационного комплекта не повторяется; актуальная проверка ru.36 остаётся 623 теста, 621 passed, 2 skipped.

## Запуск DSH

В чистом чате пользователь прикладывает ZIP. Разрешены проверка существующего шаблона через ppt_template list/get или личный импорт отсутствующего. При несовпадении шаблон не перезаписывать. Прочитать material.txt, составить компактный visualSpec с version=1, mode=demo, источником synthetic=true и двумя chart в исходном порядке. Использовать обычный ppt_create ровно один раз с title «План, факт и динамика заявок», lang=ru, templateId=user:ordinary-dark-clean-20261121. Готового JSON запроса во вложении нет; requestFile не требуется, содержание можно передать inline. Не выдумывать contentHash.

Сохранить числа, единицы, имена рядов, порядок категорий/месяцев и видимую демо-пометку. Не добавлять обложку, заключение, карточки, проценты, накопление или другие задания. Не вызывать ppt_generation, не делать дополнительных check/render/edit после успешного create. При ошибке остановиться. Выдать HTML/PPTX/PDF при наличии и предупреждения, визуальную приёмку не объявлять.

От пользователя нужны архив результата, время и оценка читаемости подписей/легенд и различимости двух рядов. Точный биллинг, число модельных вызовов и наличие шрифта на сервере по времени интерфейса не устанавливаются.
