# Профиль пользовательского шаблона для компактной генерации

Статус: экспериментальный этап 2 [плана](FEATURE-PLAN-COMPACT-GENERATION-2026-11-20.md). Профиль ещё не подключён к `ppt_create`; создание новых композиций — следующий этап.

## Содержимое

`skills/dsh-ppt/scripts/deck-generation-profile.mjs` использует существующий импорт PPTX и проверку шаблонов v3. Профиль содержит:

- версию профиля/импортера и идентичность шаблона;
- исходный физический размер страницы в EMU;
- палитру, бренд, тематические шрифты и список семейств;
- реальные ID/purpose референсов и существующие правила fallback;
- фон каждого референса: цвет или ID растрового ассета;
- типографику заголовка/основного текста и относительные compositionGuides;
- рамки и преобразованные границы фиксированного декора;
- объединённые границы образцов содержимого как ориентир;
- диагностику ограничений импорта.

Исходный текст абзацев, байты картинок и шрифтов в профиль не копируются. Имена объектов и прочие метаданные остаются данными шаблона, не инструкциями. Границы образцов — не фиксированные слоты, лимиты вместимости или доказанные безопасные области.

Шрифты всегда имеют `availability:"not-verified"`. `embeddedVariants` сообщает только об имеющихся в шаблоне файлах начертаний, проверенных существующим валидатором; это не гарантия одинакового рендера на любой машине. Фактическую замену подтверждают результаты рендера, не отсутствие шрифта в локальной установке.

## Проверка пригодности

Блокируются некорректный шаблон, отсутствующие/неверные байты ассетов, неподдержанный видимый декор без превью, сообщённая потеря фона и неподдержанные объекты импортера, отсутствующие в сцене.

С превью декор сохраняет ограничение редактируемости и предупреждение. Неподдержанный sample-контент, который обычный путь композиции удалит, не блокирует профиль. Скрытые объекты и невидимые пропуски импортера не объявляются видимой потерей оформления.

Отсутствующий cover-референс даёт предупреждение: нужен явный выбор существующего `designLayout`. Автоматической подстановки содержательного макета для обложки нет. Физический размер не меняется на 16:9.

Если отчёт импорта не сохранён в ZIP/библиотеке, профиль явно сообщает `import-history-unavailable`: утраты отсутствующих объектов проверить нельзя. Растровый фон сохраняется, но его надписи и возможность размещения нового текста требуют просмотра.

`valid:true` означает прохождение структурной проверки с учётом этих предупреждений. Это не визуальная приёмка, доказательство отсутствия коллизий или подтверждение точного совпадения с исходным PPTX.

## CLI

```powershell
node scripts/generation-profile.mjs pptx "path/to/template.pptx" template-id "Имя шаблона" local-user
node scripts/generation-profile.mjs zip "path/to/template.zip" local-user
```

CLI печатает профиль, диагностику и замеры времени как JSON. Ненулевой код означает блокирующую ошибку. Он не регистрирует шаблон, не вызывает модель и не пишет новые файлы. Перед использованием произвольного пользовательского вложения в качестве шаблона нужно получить ответ о его роли.

## API и кеш

```javascript
import {
  createGenerationProfileCache,
  prepareGenerationTemplateFromPptx,
  prepareGenerationTemplateProfile
} from './skills/dsh-ppt/scripts/deck-generation-profile.mjs'

const cache = createGenerationProfileCache()
const result = await prepareGenerationTemplateFromPptx(bytes, {
  scope: 'authorized-owner/library',
  templateId: 'corporate',
  name: 'Corporate',
  cache,
  signal
})

// Для уже загруженного из разрешённой библиотеки шаблона:
const loaded = prepareGenerationTemplateProfile(
  {manifest, assets, report},
  {scope: 'authorized-owner/library', cache}
)
```

Проверка доступа к библиотеке остаётся обязанностью вызывающей стороны. Scope разделяет кеш и не является авторизацией. Использовать непрерывно живущий кеш только внутри соответствующего сервиса; удалить его при завершении/смене нужного контекста. По умолчанию кеш ограничен 16 записями и 8 MiB сериализованных результатов; LRU-вытеснение. Исходные байты и полные manifest в кеше не хранятся; результаты возвращаются копиями.

Ключ профиля учитывает scope, версии профиля/импортера, manifest, отчёт импорта, хеши используемых изображений и файлов шрифтов. Порядок ключей объекта не влияет на хеш; порядок массивов влияет. Блокирующие результаты не кешируются.

Для прямого PPTX отдельный ключ включает хеш фактических исходных байтов, scope и параметры импорта. Повторный вызов в том же процессе пропускает импорт/построение профиля, но перечитывает и хеширует источник для обнаружения изменений. Время отражается раздельно: `sourceMs`, `importMs`, `profileMs`; при попадании в кеш `importMs` и `profileMs` равны нулю.

При изменении семантики импортера нужно увеличить `PPTX_SCENE_IMPORTER_VERSION` в `deck-pptx-scenes.mjs`; при изменении контракта профиля — `GENERATION_PROFILE_VERSION`. Межпроцессного/дискового кеша пока нет. Прогрев CLI между разными процессами не обещается.

## Проверки

```powershell
node --test test/generation-profile.test.mjs
```

Набор проверяет светлый/тёмный фон и нестандартную страницу, собственные рамки декора, правые якоря/отражение, отсутствующие ассеты, неподдержанные объекты и превью, потери фона, отсутствие истории импорта, версии/байты/изоляцию/вытеснение кеша, настоящий импорт синтетического PPTX, повтор без импорта, вложенные группы и отмену. Это структурные проверки; визуальный просмотр ещё не выполнялся.
