# Подготовленный JSON без повторного набора содержания

С ru.27 обычный ppt_create может сам прочитать локальный файл с полным JSON-запросом. Это предпочтительный путь для уже проверенного JSON с contentHash: модель передаёт короткую ссылку на файл вместо повторного набора больших текстов, неразрывных пробелов и вложенных строк.

```json
{
  "title": "<точное значение title из файла>",
  "requestFile": "<фактический локальный путь к приложенному JSON>",
  "requestSha256": "<исходный SHA-256 байтов файла, 64 строчных hex-символа>"
}
```

Не передавать одновременно inline visualSpec/tableSpec, templateId, outputDir, lang и другие переопределения. Все параметры берутся из файла, кроме title в коротком вызове: он обязателен для совместимости схемы и должен совпасть с файлом точно, включая пробелы.

Файл должен содержать один JSON-объект обычного ppt_create с title, согласованным templateId, ровно одним tableSpec или visualSpec и его исходным contentHash. Применяются прежние правила содержания, конфликты полей, права библиотеки, лимит слайдов и сессионный экспорт. Вложенные requestFile/requestSha256 запрещены. Это не внутренний project JSON, не код и не экспериментальный start/submit.

Путь относителен доверенному cwd текущей сессии либо абсолютный; это путь, доступный самому процессу плагина. Не передавать Windows-путь оператора на Linux-сервер. Если файл виден только инструменту Bash в другом контейнере и недоступен плагину, вернуть ошибку доступа; не переходить молча к переписыванию inline-входа. URL не загружаются. Принимается обычный файл 1–33554432 байта со строгим UTF-8 и валидным JSON; UTF-8 BOM разрешён и учитывается в байтовой сумме.

requestSha256 — сумма исходных байтов всего файла. Это не contentHash: последняя проверяет каноническое содержание spec, а не байтовый формат JSON. Порядок ключей/отступы/переводы строк могут менять байтовую сумму даже при прежнем contentHash. Сохранять обе предоставленные суммы; нельзя удалять или пересчитывать их ради принятия изменённого входа. При подготовке нового проверенного файла интеграция вычисляет обе суммы до передачи пользователю. Ошибки чтения/разбора/проверки останавливают вызов без повторов и исправления источника.

Плагин читает и разбирает файл сам, не изменяя его. Результат requestInput содержит sha256 и bytes фактически прочитанного файла; не трактовать эту квитанцию как визуальную приёмку. Обычная выдача — HTML/PPTX/PDF при наличии и существенные предупреждения, без автоматического цикла расширенной проверки. Внутренний проект не прикладывать по умолчанию.
