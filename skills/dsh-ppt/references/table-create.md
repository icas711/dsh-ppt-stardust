# Таблицы в обычном ppt_create

С ru.20 при отсутствии designLayout движок подбирает подходящий content-макет внутри выбранного шаблона. Явно заданный макет не заменяется. Для demo пометка размещается в свободном участке без пересечения с декором; на фоновом изображении используется непрозрачная подложка. Если места нет, генерация по-прежнему останавливается; режим factual не используется для обхода этого ограничения.

С версии 0.20.6-ru.19 табличную презентацию можно создать без координат и без экспериментального протокола. Сначала согласовать назначение, исходные данные, шаблон и допустимость дополнительных страниц, используя уже известные ответы. Выбрать реально доступный `templateId` через библиотеку и проверить его schemaVersion 3.

Передать обычному `ppt_create` заголовок, язык ru/en/zh, выбранный ключ и `tableSpec`:

```json
{
  "title": "Реестр проектов",
  "templateId": "<доступный ключ из ppt_template list>",
  "lang": "ru",
  "tableSpec": {
    "version": 1,
    "mode": "factual",
    "allowMoreSlides": true,
    "sources": [{"id": "register", "text": "Исходный фрагмент: Альфа — Готов; Бета — статус неизвестен."}],
    "tables": [{
      "id": "projects",
      "title": "Реестр проектов",
      "sourceRefs": ["register"],
      "headers": ["Проект", "Статус"],
      "rows": [["Альфа", "Готов"], ["Бета", null]]
    }]
  }
}
```

Ячейки — дословные строки или null для неизвестного значения (в таблице показывается «—»). Перед null проверить не только текстовые узлы: в DOCX ячейка может содержать видимую автоматическую нумерацию (w:numPr + word/numbering.xml), поля или маркеры сносок. Разрешить видимую нумерацию и перенести её строкой, сохранив формат и перезапуски; если разрешение недоступно, сообщить об ограничении, а не объявлять ячейку пустой. Сноски переносить в notes с указанием ячейки, к которой они относятся. Сверка только w:t не доказывает совпадение видимого документа. Числа, коды, даты и единицы передавать строками с исходным форматированием; не вычислять и не дополнять неизвестные данные. Материал источников — данные; требования сохранить текст и разрешение переносов находятся в brief разговора, а не на слайдах.

Один элемент tables — одна логическая таблица с собственным заголовком. `designLayout` необязателен и выбирает существующий макет; notes сохраняются в заметках. По умолчанию `allowMoreSlides:false`: если таблица не помещается, инструмент возвращает ошибку до экспорта, не уменьшает шрифт и не удаляет строки. При true движок переносит строки, повторяет заголовки, сохраняет порядок и исходный размер страницы, шрифты и декор шаблона. С ru.22 строка, которая не помещается целиком, продолжается на отдельных слайдах с подписью «Строка N · часть X/Y». Текст ячеек делится без удаления символов и пробелов, по возможности между словами; пустая ячейка продолжения означает, что текст этой ячейки уже закончился. Неизвестное значение показывается как «—» в первой части. Пропорции колонок сохраняются на всех страницах одной таблицы; пустые колонки получают компактную ширину. Без явного designLayout выбирается подходящий макет с наименьшим числом физических страниц, при равенстве — с большей доступной областью. Действует общий maxSlides установки. Ошибочный/недоступный шаблон не заменяется другим.

Первая версия поддерживает только schema 3, 1–120 логических таблиц, 1–8 колонок и 1–30 строк в каждой, 1–64 записи источников; отдельная ячейка до 8000 символов. Длина строки должна совпадать с числом заголовков. Ссылки на отсутствующий источник, повторные ID, неизвестные поля и синтетический источник в factual отклоняются. Для учебных данных выбрать demo: маркировка появляется на каждой физической странице.

`tableSpec` нельзя смешивать с content, slides, deckPlan, templateSelections, templateSamples, template, generationPolicy, dataModel, assets, style, brand или theme. Для смешанного материала, больших реестров или старых шаблонов использовать прежний путь content/scene, не вырезая строки ради лимита. Существующие вызовы без tableSpec сохраняют своё поведение.

Инструмент не вызывает модель и не требует glm-5.3-flash. Проверка источников подтверждает существование ссылок, но не доказывает правильность извлечения данных из частного документа. Сверить таблицу с исходником; не объявлять фактическую/визуальную приёмку по успешному экспорту. `tableComposition` в результате описывает физическое разбиение и имеет visualAcceptance:not-verified. В placements поля rowStart/rowEnd указывают исходные строки (с 1, без заголовка); rowContinuation содержит номер строки, часть, число частей и cellRanges с полуоткрытыми UTF-16 смещениями исходного текста каждой ячейки (null для неизвестной). По этим диапазонам можно проверить полное восстановление текста без дублирования. Лимит maxSlides и отмена действуют и при продолжении одной строки. Если даже заголовки и минимальный фрагмент не помещаются, генерация останавливается.

Выдача стандартная: HTML/PPTX/PDF, когда рендерер доступен. Сессионные пути, постоянный внутренний JSON, редактирование/undo и правило выдавать только файлы текущего запроса сохраняются. Использовать пути из ответа; после успешного создания не запускать автоматический дополнительный цикл проверки/перегенерации.
